# Schism6 策略：会"思考时间"的智能抄底侠

> **外号**：时间哲学家
> **职业**：趋势回调猎手
> **时间框架**：5 分钟 + 1 小时双引擎

---

## 一、这策略是个啥？

简单说，**Schism6** 就是一个：
- 双时间框架分析（大周期看方向，小周期找入场）
- 动态参数系统（持仓越久，规则越宽容）
- 智能仓位管理（盯着全局槽位做决策）

就像一个**有大局观的短线交易员**，先看 1 小时大势，再在 5 分钟图里找回调机会，而且持仓时间越长越有耐心 🎯

---

## 二、核心配置：说白了就是"见好就收，但不急着跑"

### 止盈规则（ROI 表）

```
立即    → 2.5% 利润就考虑出
10分钟  → 降到 1.5% 也行
20分钟  → 1% 也不嫌弃
30分钟  → 0.5% 也就是一顿饭钱
2小时   → 保本也走人
```

**翻译**：这策略属于"短线快手"，赚钱就走，不贪心。2 小时还不出利润？那就保本撤退，不做时间的朋友。

### 止损规则

```
硬止损：-10%（最后防线）
动态止损：持仓 0 分钟 -3%，持仓 5 小时保本
```

**翻译**：刚进场时止损严格（-3%），持仓越久越宽容，给趋势发展的时间。

## 三、买入条件：分两种情况，各有各的道理

### 🎯 情况一：空仓时怎么买？

这策略的入场逻辑有点绕，我给你拆开说：

**先看大方向（1小时级别）**：
- RSI >= 65 → 市场强势，不在弱势中抄底

**再看具体位置（价格）**：
- 价格 <= 3日最低价 + 87% 的波动范围
- 意思是：在支撑位附近入场

**最后看入场时机（RMI 指标）**：
- RMI 慢速 >= 33（不是极端弱势）
- RMI 快速 <= 41（快速线没超买）
- RMI 下降趋势中（正在回调）

**大白话**：
> "大周期强势，小周期回调，位置在支撑附近，这时候我出手。"

**经典台词**：
- 条件：`RSI(1h) >= 65` → "大势所趋，顺势而为"
- 条件：`价格 <= 3日低 + 87% ADR` → "便宜不占白不占"
- 条件：`RMI 下降趋势` → "别人恐惧我贪婪"

---

### 🔄 情况二：有仓时怎么加？

已经有仓位了？策略会判断能不能加：

**条件**：
1. RMI 上升趋势（趋势还在延续）
2. 当前利润 > 峰值利润 × 动态因子
3. RMI 慢速 >= 线性增长阈值

**线性增长是个啥？**

```
持仓 3 小时 → 加仓门槛 RMI >= 30
持仓 6 小时 → 加仓门槛 RMI >= 50
持仓 12 小时 → 加仓门槛 RMI >= 70
```

**大白话**：
> "持仓时间越长，加仓门槛越高。刚买的可以加，买了半天的别乱动。"

这是为了**防止高位加仓**，保护已有利润。

## 四、卖出逻辑：三个信号，一个比一个有脑子

### 4.1 动态止损：时间越久越宽容

```
刚进场     → 亏 3% 就止损
持仓 2.5小时 → 亏 1.5% 止损
持仓 5 小时  → 保本就跑
```

**大白话**：
> "新开的仓严格止损，老仓给机会翻盘。"

### 4.2 趋势反转信号

| 场景 | 触发条件 | 大白话 |
|------|---------|--------|
| 有利润过 | RMI 下穿 50 | "趋势转弱，该走了" |
| 没赚过钱 | RMI 下穿 10 | "彻底不行，割肉吧" |

### 4.3 槽位管理：全局眼光

这是这策略最聪明的地方：

```python
if 有空闲槽位:
    其他交易对平均要盈利才能卖
    # 避免卖早了错过反弹
else:
    只卖最亏的那个
    # 槽位紧张时，优先释放最差的仓位
```

**大白话**：
> "槽位还有空，我不急；槽位满了，先把最亏的清掉。"

## 五、这策略的"人格特点"

### ✅ 优点（夸夸环节）

1. **多周期确认**：不是瞎抄底，先看大周期再动手
2. **动态风控**：持仓时间自动调整风险参数，人性化
3. **全局视角**：盯着所有仓位做决策，不是孤立看单笔交易
4. **峰值保护**：赚过钱了就设保护，不让利润变亏损
5. **入场确认**：限价单如果偏离太多会拒绝，防止滑点

### ⚠️ 缺点（吐槽环节）

1. **复杂度高**：参数多到头大，新手容易晕
2. **依赖实盘数据**：回测时加仓逻辑跑不了，实盘才能验证
3. **计算开销大**：每次都查数据库，交易对多了会慢
4. **调参困难**：买入参数是优化过的，换市场可能要重来

## 八、想跑这个策略？先看看这些配置

### 8.1 交易对配置

| 配置项 | 建议值 | 吐槽 |
|--------|--------|------|
| startup_candle_count | 72 | 需要足够历史数据算指标 |
| inf_timeframe | 1h | 可以改成 4h 试试 |
| stoploss | -0.10 | 默认值，看你风险偏好 |

### 8.2 硬件要求（重要！）

这策略每次都要查数据库，对 VPS 有要求：

| 交易对数量 | 最低内存 | 推荐内存 | 体验 |
|-----------|---------|---------|------|
| 1-10 对 | 2GB | 4GB | 流畅 |
| 11-30 对 | 4GB | 8GB | 还行 |
| 30+ 对 | 8GB | 16GB | 得配好机器 |

**警告**：交易对多了，`populate_trades` 会变成性能瓶颈 😅

### 8.3 回测 vs 实盘

**坑来了**：回测时 `populate_trades` 返回空数据，所以：
- 加仓逻辑不会触发
- 槽位管理逻辑不会执行
- 动态止损只能靠 ROI 表

**建议流程**：
1. 先回测验证基础逻辑
2. dry_run 跑几天看加仓效果
3. 小资金实盘验证
4. 逐步放大仓位

**别一上来就梭哈**，这策略回测和实盘差异挺大的！

## 九、彩蛋：策略作者的"小心思"

仔细看代码，你会发现一些有趣的设计：

1. **TTLCache 缓存**：当前价格缓存 5 分钟
   > "别频繁调 API，交易所会封你的"

2. **订单超时取消**：价格偏离 1% 就取消订单
   > "滑点太大不干，这是原则问题"

3. **入场确认**：同样价格偏离 1% 就拒绝
   > "限价单就按限价来，别想蒙我"

4. **ignore_roi_if_buy_signal**：有买入信号时忽略 ROI
   > "还看啥 ROI，加仓机会来了！"

## 十一、⚠️ 风险再强调（这段一定要看）

### 回测很美好，实盘要谨慎

Schism6 的设计很精巧——但这有个陷阱：

> **因为回测时加仓逻辑跑不了，实盘可能和回测表现差异巨大。**

简单说就是：**回测看的只是基础逻辑，加仓才是策略的灵魂。**

### 复杂策略的隐藏风险

实盘时，复杂的逻辑可能导致：
- **数据库查询慢**：交易对多了会卡
- **动态参数漂移**：持仓时间计算可能有偏差
- **滑点风险**：5 分钟级别波动大
- **API 限流**：频繁查价格可能被封

### 我的建议（真心话）

```
1. 小资金起步，别超过总仓位的 10%
2. 先跑几个交易对，别贪多
3. 每天看日志，理解策略决策
4. 记录每次加仓和止损的触发
5. 根据实盘表现微调参数
```

**记住**：策略再好，市场教做人时也不会打招呼。轻仓测试，活着最重要！🙏
