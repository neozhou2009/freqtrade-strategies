## 一、策略概览

**Schism2** 是由 @werkkrew 和 @JimmyNixx 开发的高级趋势跟踪策略，是 Schism 框架的进化版本。策略特色是使用了动态买卖信号、多时间框架确认、以及基于交易状态的动态退出逻辑。策略支持 BTC/ETH 质押的额外确认逻辑。

### 核心特征

| 特征 | 描述 |
|------|------|
| **买入条件** | 多条件组合（RMI + ADR + 多时间框架） |
| **卖出条件** | 动态止损 + ROI 退出 |
| **保护机制** | 自定义交易数据管理 + 价格缓存 |
| **时间框架** | 5 分钟 |
| **依赖库** | TA-Lib, technical, numpy, cachetools |
| **特殊功能** | 动态交易数据、多时间框架、BTC/ETH 质押支持 |

- **长持仓保护**：1440 分钟（24 小时）后保本退出

## 三、买入条件详解

### 3.1 买入逻辑（无持仓时）

```python
# 主要买入条件
(
    (close <= 3d_low + (inf_pct_adr * adr)) &  # 价格 <= 3 日低点 + ADR 百分比
    (rsi_1h >= inf_rsi) &                       # 1h RSI >= 阈值
    (rmi_dn_trend == 1) &                       # RMI 下降趋势
    (rmi_slow >= rmi_slow_param) &              # RMI 慢速 >= 阈值
    (rmi_fast <= rmi_fast_param) &              # RMI 快速 <= 阈值
    (mp <= mp_param) &                          # Momentum Pinball <= 阈值
    (volume > 0)                                 # 成交量 > 0
)
```

**逻辑解析**：
- **ADR 回调**：价格回调至 3 日低点 + ADR 百分比
- **1h RSI 确认**：1 小时 RSI 高于阈值
- **RMI 趋势**：RMI 下降趋势确认
- **Momentum Pinball**：动量指标确认超卖

### 3.2 买入逻辑（有持仓时）

```python
# 持续买入条件（忽略 ROI）
(
    (rmi_up_trend == 1) &                              # RMI 上升趋势
    (current_profit > peak_profit * profit_factor) &   # 当前利润 > 峰值利润×因子
    (rmi_slow >= rmi_grow) &                           # RMI 慢速 >= 增长值
    (volume > 0)                                        # 成交量 > 0
)
```

**作用**：
- 在趋势中持续买入
- 利用 `ignore_roi_if_entry_signal = True` 阻止过早退出

### 3.3 BTC/ETH 质押额外确认

```python
# 如果质押是 BTC 或 ETH
if stake_currency in ("BTC", "ETH"):
    # 默认时间框架条件
    (stake_rsi < xtf_stake_rsi) | (fiat_rsi > xtf_fiat_rsi)
    # 信息时间框架条件
    stake_rmi_1h < xinf_stake_rmi
```

**作用**：
- 根据质押货币和法币 RSI 确认
- 多一层趋势确认

## 四、卖出逻辑详解

### 4.1 动态止损逻辑

```python
# 如果处于亏损状态
if current_profit < loss_cutoff:  # loss_cutoff 从 -0.03 增长到 0
    if rmi_dn_trend == 1:  # RMI 下降趋势
        # 如果峰值利润曾为正但从未达到 ROI
        if peak_profit > 0:
            crossed_below(rmi_slow, 50)  # RMI 慢速下穿 50
        else:
            crossed_below(rmi_slow, 10)  # RMI 慢速下穿 10
```

**作用**：
- 动态止损阈值（从 -3% 增长到 0%）
- 根据峰值利润调整退出条件

### 4.2 多交易状态管理

```python
# 如果有其他开放交易
if other_trades:
    if free_slots > 0:
        # 根据空闲仓位调整退出阈值
        max_market_down = -0.04
        hold_pct = (1 / free_slots) * max_market_down
        avg_other_profit >= hold_pct
    else:
        # 如果没有空闲仓位，允许最大亏损交易退出
        biggest_loser == True
```

**作用**：
- 根据空闲仓位调整退出策略
- 优先释放亏损最大的仓位

def populate_trades(self, pair: str) -> dict:
    # 获取当前价格
    current_rate = self.get_current_price(pair, True)
    # 计算当前利润
    current_profit = active_trade[0].calc_profit_ratio(current_rate)
    # 计算峰值利润
    peak_profit = max(0, active_trade[0].calc_profit_ratio(active_trade[0].max_rate))
    # 计算开放分钟数
    open_minutes = (present - trade_start).total_seconds() // 60
    # 获取其他交易平均利润

    free_slots = max(0, max_open_trades - open_trades)

## 七、策略优势与局限

### ✅ 优势

1. **动态买卖逻辑**：根据交易状态动态调整
2. **多时间框架确认**：1h 信息时间框架确认趋势
3. **多交易状态管理**：根据空闲仓位调整退出策略
4. **BTC/ETH 质押支持**：额外的质押货币确认
5. **价格缓存**：减少 API 调用，提高效率
6. **超参数优化**：支持 Hyperopt 优化关键参数

### ⚠️ 局限

1. **复杂度极高**：动态逻辑 + 多时间框架，调试困难
2. **仅支持实盘**：动态交易数据在回测中不可用
3. **无 BTC 大盘关联**：不检测比特币大盘趋势（除非质押是 BTC）
4. **计算量大**：多指标 + 动态数据增加计算负担
5. **参数敏感**：超参数优化结果可能过拟合

## 十、重要提醒：动态交易状态的使用

### 10.1 学习成本极高

策略代码约 400 行，需要理解动态交易状态、多时间框架、价格缓存等复杂概念。

### 10.2 硬件要求高

多指标 + 动态数据增加计算量：

| 交易对数量 | 最低内存 | 推荐内存 |
|-----------|---------|---------|
| 20-40 对 | 2GB | 4GB |
| 40-80 对 | 4GB | 8GB |

### 10.3 仅支持实盘

动态交易数据在回测和 Hyperopt 中不可用：
- `populate_trades()` 函数仅在 live/dry_run 模式下工作
- 回测无法测试动态买卖逻辑
- 实盘前需充分干跑测试

### 10.4 手动交易者建议

手动交易者可参考此策略的动态思路：
- 根据交易状态调整买卖决策
- 使用多时间框架确认趋势
- 根据空闲仓位调整退出策略
