# Schism2 策略：抄底界的"全栈大师"

> **外号**：全栈抄底王、多货币适配专家、Per-pair 定制达人

## 一、这策略是个啥？

简单说，**Schism2** 就是：
- Schism 的升级版——保留所有核心功能
- 多货币适配——不只是 USDT，BTC/ETH 也完美支持
- Per-pair 定制——每个币可以有自己的参数
- 还带两个"小弟"——Schism2_BTC 和 Schism2_ETH 子策略

就像 **Schism 学会了新技能：会看 BTC/ETH 的脸色，会给不同币定制方案，还能变身适应不同场景** 🎯

**一句话总结**：
> "我继承了 Schism 的抄底哲学，但我还能看 stake currency 的状态，给不同币定制参数，适应 BTC 和 ETH stake。"

## 四、保护机制：继承 + 新增

### 4.1 继承的 4 层保护

| 保护类型 | 作用 | 大白话 |
|---------|------|--------|
| **硬止损** | -30% 直接砍 | "跌到 -30% 认栽，保命要紧（比 Schism 的 -40% 更安全）" |
| **动态止损** | -3% → 0% | "时间越久，止损越紧" |
| **订单超时** | 滑点 > 1% 取消 | "价格跑太快就不买了/不卖了" |
| **入场确认** | 滑点 > 1% 拒绝 | "下单前再确认一次价格，别被坑" |

### 4.2 新增：Per-pair 参数隔离

**大白话**：
> "Schism2 还能给每个币定制参数！不是一刀切，而是'因币制宜'。"

**配置示例**：

```python
custom_pair_params = [
    {
        'pairs': ['BTC/USDT', 'ETH/USDT'],
        'buy_params': {'inf-rsi': 40, 'mp': 50},
        'minimal_roi': {"0": 0.08, "30": 0.04}
    },
    {
        'pairs': ['DOGE/USDT'],
        'buy_params': {'inf-rsi': 25, 'mp': 70},
        'minimal_roi': {"0": 0.15, "60": 0.05}
    }
]
```

**大白话翻译**：
- **"BTC/ETH 这些稳币，参数宽松点，ROI 也不用太激进"**
- **"DOGE 这种疯狗币，参数更激进，ROI 也设高点——别让疯狗跑太快"**

## 六、这策略的"人格特点"

### ✅ 优点（夸夸环节）

1. **继承 Schism 的所有优点**：抄底有原则、趋势骑乘、全局视角、多层保护
2. **多货币适配**：BTC/ETH stake 完美支持，自动添加 COIN/FIAT 信息对
3. **Per-pair 定制**：每个币可以有自己的参数，不再一刀切
4. **子策略扩展**：Schism2_BTC 和 Schism2_ETH 针对不同场景优化
5. **更保守的止损**：-30% vs Schism 的 -40%，风险更可控

### ⚠️ 缺点（吐槽环节）

1. **只适合实盘**：核心功能回测用不了，和 Schism 一样
2. **参数更多**：买参数 8 个（Schism 是 5 个），优化难度更大
3. **API 调用多**：BTC/ETH stake 需要额外信息对，网络开销增加
4. **配置更复杂**：Per-pair 参数、子策略、多货币……新手可能晕
5. **过拟合风险更高**：参数多了，更容易"背答案"

### 10.3 硬件要求（重要！）

这策略计算量更大，对 VPS 有更高要求：

| 交易对数量 | Stake 类型 | 最低内存 | 推荐内存 | 体验 |
|-----------|-----------|---------|---------|------|
| 1-10 对 | USDT | 2 GB | 4 GB | 流畅 |
| 1-10 对 | BTC/ETH | 4 GB | 8 GB | 需更多 API |
| 10-30 对 | USDT | 4 GB | 8 GB | 可能有点卡 |
| 10-30 对 | BTC/ETH | 8 GB | 16 GB | API 调用多 |
| 30+ 对 | 任意 | 16 GB | 32 GB | 老机器会叫苦 |

**警告**：BTC/ETH stake 需要额外的信息对 API 调用，网络延迟和内存开销都会增加！😅

### 10.4 回测 vs 实盘

**大坑警告**：
- 和 Schism 一样，核心功能（持仓延续信号、全局仓位感知）**只在实盘/干跑中生效**
- 回测时无法获取 `Trade.get_trades()` 数据
- BTC/ETH 信息对在回测中可能无法正确加载
- **回测结果和实盘表现可能有显著差异**

**建议流程**：
1. 先用 Schism 熟悉核心逻辑

## 十一、彩蛋：策略作者的"小心思"

仔细看代码，你会发现一些有趣的东西：

1. **子策略的设计哲学**：

4. **profit_factor 的数学美**：
   > `profit_factor = 1 - (rmi_slow / 400)` —— RMI 越高，对利润要求越低。这个公式从 Schism 继承过来，依然优雅。

## 十三、⚠️ 风险再强调（这段一定要看）

### 回测很美好，实盘要谨慎

Schism2 的历史回测表现往往**很好看**——但这有个陷阱：

> **核心功能（持仓延续信号、全局仓位感知）在回测中不生效，而且 BTC/ETH 信息对在回测中可能无法正确加载！**

简单说就是：**回测看到的不是真实的策略行为。**

### 复杂策略的隐藏风险

实盘时，复杂的逻辑可能导致：
- **API 调用延迟**：BTC/ETH stake 需要额外信息对，网络延迟风险增加
- **数据库访问延迟**：查询其他交易状态需要时间，极端行情下可能来不及
- **Per-pair 配置错误**：参数配置复杂，一个错误可能导致策略失效
- **内存溢出**：多交易对 + 多信息对，内存占用可能超标
- **参数过拟合**：8 个买参数 + Per-pair 配置，过拟合风险比 Schism 更高

### Schism2 vs Schism 选择指南

| 场景 | 推荐 |
|------|------|
| 新手玩家 | Schism（更简单） |
| USDT stake | Schism 或 Schism2（差异不大） |
| BTC/ETH stake | Schism2（必须用） |
| 需要定制参数 | Schism2（Per-pair 支持） |
| 追求极简 | Schism（参数少） |
