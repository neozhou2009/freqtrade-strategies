## 一、策略概览

BB_RPB_TSL_c7c477d_20211030 是一个基于布林带（Bollinger Bands）突破与回调买入相结合的策略，配备多层动态追踪止损机制。策略融合了 RPB（Real Pull Back）理念和 BigZ04_TSL 的自定义止损逻辑，通过 Hyperopt 参数优化实现精细化配置。

### 2.2 自定义追踪止损机制

```python
# 追踪止损参数（来自 Hyperopt 优化）
pHSL = -0.178   # 硬止损利润基准
pPF_1 = 0.01    # 第一利润阈值（1%）
pSL_1 = 0.009   # 第一止损值（0.9%）
pPF_2 = 0.048   # 第二利润阈值（4.8%）
```

**止损逻辑**：
- 利润 < 1%：使用硬止损 pHSL（-17.8%）
- 利润 1% ~ 4.8%：止损值在 SL_1 和 SL_2 之间线性插值
- 利润 > 4.8%：止损值随利润线性增长（利润越高，保护越紧）

## 六、风险管理特色

### 6.1 BTC 大盘保护

策略内置 BTC/USDT 双重暴跌保护：

| 保护层级 | 检测周期 | 触发条件 |
|---------|---------|---------|
| **5 分钟保护** | 5m | BTC 5 分钟跌幅超过阈值（默认 -289） |
| **1 天保护** | 1d | BTC 1 天跌幅超过阈值（默认 -5%） |

**逻辑**：当 BTC 大盘暴跌时，暂停所有买入操作，避免在下跌趋势中建仓。

### 6.2 自定义追踪止损

动态止损机制实现利润保护：

```python
def custom_stoploss(...):
    if (current_profit > PF_2):  # 利润 > 4.8%
        sl_profit = SL_2 + (current_profit - PF_2)  # 止损随利润增长
    elif (current_profit > PF_1):  # 利润 1% ~ 4.8%
        sl_profit = SL_1 + ((current_profit - PF_1) * (SL_2 - SL_1) / (PF_2 - PF_1))  # 线性插值
    else:  # 利润 < 1%
        sl_profit = HSL  # 硬止损
```

## 七、策略优势与局限

### ✅ 优势

1. **多层买入信号**：7 个独立买入条件，提高入场机会覆盖率
2. **BTC 大盘保护**：双重暴跌保护，避免在恶劣市场环境下建仓
3. **动态追踪止损**：分级止盈机制，利润越高保护越紧
4. **Ichimoku 云图确认**：1 小时信息层提供趋势方向确认
5. **Hyperopt 优化友好**：大量参数可优化，便于适配不同市场

### ⚠️ 局限

1. **参数复杂**：超 30 个 Hyperopt 参数，优化难度较高
2. **BTC 依赖**：需要 BTC/USDT 数据，多币种策略需配置 BTC 信息对
3. **计算密集**：大量指标计算，对硬件有一定要求
4. **无卖出信号**：主要依赖追踪止损离场，主动卖出信号较少

## 九、适用市场环境详解

BB_RPB_TSL 系列是布林带策略家族的重要成员。基于其代码架构和社区长期实盘验证的经验，它最适合 **震荡偏上涨的市场**，而在 **BTC 暴跌或极端下跌** 时表现不佳。

### 9.1 策略核心逻辑

- **超卖反弹**：通过 RMI/CCI/SRSI 检测超卖状态，等待布林带突破确认
- **趋势回调**：在上升趋势中等待价格回调至布林带下轨
- **大盘保护**：BTC 暴跌时自动禁用买入，避免逆势建仓
- **动态止损**：利润越高止损越紧，保护盈利同时给予波动空间

### 9.2 不同市场环境表现

| 市场类型 | 表现评级 | 原因分析 |
| :--- | :--- | :--- |
| 📈 慢牛上涨 | ⭐⭐⭐⭐⭐ | 超卖反弹和趋势回调信号均可有效触发 |
| 🔄 震荡盘整 | ⭐⭐⭐⭐☆ | 超卖反弹策略表现良好，但止损可能频繁触发 |
| 📉 持续下跌 | ⭐⭐☆☆☆ | BTC 保护机制频繁生效，买入机会少 |
| ⚡️ BTC 暴跌 | ⭐☆☆☆☆ | 买入被自动禁用，策略进入休眠状态 |

### 9.3 关键配置建议

| 配置项 | 建议值 | 说明 |

- 布林带突破与回调的含义

### 10.2 硬件要求

| 交易对数量 | 最低内存 | 推荐内存 |
|-----------|---------|---------|
| < 10 对 | 2 GB | 4 GB |
| 10 ~ 30 对 | 4 GB | 8 GB |

### 10.3 回测与实盘的差异

回测时 BTC 保护机制基于历史数据，实盘中 BTC 实时数据可能产生不同的保护效果。建议：
- 使用 Dry-run 模式测试 BTC 保护效果
- 观察 BTC 暴跌时策略是否正确禁用买入

### 10.4 手动交易者建议

不建议手动执行此策略，原因：
- BTC 保护需要实时监控 BTC/USDT 数据
- 7 个买入条件判断复杂，手动难以实时决策
- 自定义追踪止损需要动态计算，手动难以精确执行
