## 一、策略概览

**Nostalgia** 是一个高度复杂的多条件量化交易策略，专为 Freqtrade 交易平台设计。从名字来看，它可能是一个经典策略的现代重构版本，融合了多种经典技术指标和风险管理方法。

### 核心特征

| 特征 | 描述 |
|------|------|
| **买入条件** | 31 个独立买入信号，每个条件可独立启用/禁用 |
| **卖出条件** | 8 个基础卖出信号 + 多层动态止盈逻辑 |
| **保护机制** | 31 组买入保护参数（EMA/SMA/安全下跌/安全上涨） |
| **时间框架** | 5 分钟主时间框架 + 1 小时信息时间框架 |
| **依赖库** | TA-Lib, technical, qtpylib |

## 二、策略配置解析

### 2.1 基础风险参数

```python
# ROI 退出表（时间: 最小利润率）
minimal_roi = {
    "0": 0.10,    # 立即退出：10% 利润
    "30": 0.05,   # 30 分钟后：5% 利润
    "60": 0.02,   # 60 分钟后：2% 利润
}

# 止损设置
stoploss = -0.10  # -10% 硬止损

# 追踪止损
trailing_stop = True
trailing_only_offset_is_reached = True
trailing_stop_positive = 0.01    # 1% 追踪启动点
trailing_stop_positive_offset = 0.03  # 3% 偏移触发
```

**设计思路**：
- 采用**时间递减 ROI** 策略，持仓时间越长，退出门槛越低
- 配合**追踪止损**锁定利润，适合趋势行情
- 硬止损 -10% 控制单笔最大亏损

### 2.2 订单类型配置

```python
order_types = {

    "stoploss": "limit",   # 限价止损单
    "stoploss_on_exchange": False,
    "exit_timeout_count": 0,
}
```

## 三、买入条件详解

### 3.1 保护机制（31 组）

每个买入条件都配有独立的保护参数组，包括：

| 保护类型 | 参数说明 | 默认值示例 |
|---------|---------|-----------|
| **EMA 快速** | 快速 EMA 是否在 EMA200 之上 | ema_fast_len=26 |
| **EMA 慢速** | 1h 慢速 EMA 是否在 EMA200 之上 | ema_slow_len=100 |
| **收盘价保护** | 收盘价是否在 EMA 之上 | close_above_ema_fast_len=200 |
| **SMA200 上升** | SMA200 是否处于上升趋势 | sma200_rising_val=28 |
| **安全下跌** | 下跌幅度阈值保护 | safe_dips_type=80 |
| **安全上涨** | 上涨幅度阈值保护（防追高） | safe_pump_type=70 |
| **BTC 趋势** | BTC 1h 是否非下跌趋势 | btc_1h_not_downtrend |

### 3.2 典型买入条件示例

#### 条件 #1：RSI 超卖 + MFI 低值
```python
# 逻辑
- RSI(1h) 在 30-84 之间
- RSI(14) < 36（超卖区域）
- MFI < 44（资金流偏低）
- 价格相对 36 周期最低点有最小涨幅
```

#### 条件 #2：布林带下轨突破
```python
# 逻辑
- RSI < RSI(1h) - 39（相对弱势）
- MFI < 49
- 收盘价 < 布林带下轨 × 0.983（深度跌破）
```

#### 条件 #3：布林带 40 周期反转
```python
# 逻辑
- BB40 下轨 > 0
- BB40 带宽变化 > 收盘价 × 5.9%
- 收盘变化 > 收盘价 × 2.3%
- 尾部 < BB40 带宽 × 41.8%
- 收盘价 < 前一根 BB40 下轨
```

#### 条件 #5-7：EMA 交叉 + 布林带
```python
# 共同逻辑
- EMA26 > EMA12（金叉）
- EMA 差值 > 开盘价 × 系数
- 收盘价 < 布林带下轨 × 偏移系数
```

### 4.2 特殊卖出场景

## 五、技术指标体系

- EMA/SMA 趋势确认

- 拉盘/下跌保护检测（24h/36h/48h）

## 六、风险管理特色

### 6.1 下跌保护（Safe Dips）

11 级下跌阈值保护，从严格到宽松：

```
级别    阈值 1    阈值 2    阈值 3    阈值 4
────────────────────────────────────────────
10     1.5%     10%      24%      42%
50     2.0%     14%      32%      50%
80     2.4%     22%      38%      66%
100    2.6%     24%      42%      80%
110    2.7%     26%      44%      84%
```

### 6.2 拉盘保护（Safe Pump）

12 级拉盘检测，防止追高：

- 检测周期：24h / 36h / 48h
- 阈值范围：0.42 - 2.0（42% - 200% 涨幅）
- 回撤阈值：1.4 - 3.0

### 6.3 持仓保护（Hold Trades）

支持外部配置文件 `hold-trades.json`，可指定特定交易对持有至目标利润率：

```json
{
  "profit_ratio": 0.005,
  "trade_ids": [123, 456]
}
```

## 七、策略优势与局限

### ✅ 优势

1. **高度可配置**：31 个买入条件可独立启用，适应不同市场环境
2. **多层保护**：31 组保护参数 + 11 级下跌保护 + 12 级拉盘保护
3. **动态止盈**：根据利润率和 RSI 动态调整退出点
4. **多时间框架**：5m 执行 + 1h 趋势确认 + BTC 关联分析
5. **经典指标组合**：融合布林带、RSI、EMA、EWO 等经典指标

### ⚠️ 局限

1. **复杂度高**：参数众多，优化和调试难度大
2. **依赖历史数据**：需要充足的 1h 和 5m 历史数据
3. **外部依赖**：需要 TA-Lib 和 technical 库支持
4. **过度拟合风险**：31 个条件可能导致过拟合历史数据
5. **计算密集**：每个周期需计算大量指标，对性能有要求

## 九、适用市场环境详解

NostalgiaForInfinity (NFI) 是目前 Freqtrade 生态中最知名、最复杂的开源策略之一。它并非依靠单一逻辑，而是通过**数十种买入条件、多层趋势过滤和动态风险管理系统**来应对复杂多变的加密市场。

基于其代码架构和社区长期实盘验证的经验，它最适合**有明显趋势的震荡上涨市**，而在单边暴跌或横盘震荡时表现不佳。

### 9.1 策略核心逻辑：复杂性构建的"防御网"

NFI 策略的代码量通常在 1 万行以上，其核心架构决定了它更倾向于**追求高胜率**而非单笔暴利。

- **多维度入场条件**：策略内置了 20-40 种不同的买入条件（如超跌反弹、趋势突破、回调确认等）。你不需要猜测哪种行情会来，策略会自动根据当前市场环境触发相应的买入逻辑。
- **严格的风险过滤**：这是该策略的精髓。它会实时检测"24h/36h/48h 涨幅"（Pump Detection），避免追高；同时通过"BTC 1h 趋势检测"，如果比特币大盘处于下跌趋势，策略会暂停大部分山寨币的买入，这在币圈是极其重要的生存法则。
- **动态持仓管理**：不同于简单的网格或马丁格尔策略，NFI 支持"Hold Support"功能。允许针对特定的亏损单设置"不到盈利不离场"的规则，或者针对不同交易对设定差异化的止盈目标，这大大增强了扛单能力。

### 9.2 不同市场环境表现

| 市场类型 | 表现评级 | 原因分析 |
| :--- | :--- | :--- |
| 📈 慢牛/震荡向上 | ★★★★★ (最佳) | 策略内置的 EMA/SMA 趋势过滤会在趋势向上时开启更多买入条件，通过回调买入（Dip Buying）在上涨趋势中不断积累仓位，盈利能力最强。 |
| 🔄 宽幅震荡 | ★★★☆☆ (中性) | 依靠其众多的止盈条件（如遇到阻力位自动卖出）可以捕捉一些波段利润。但由于震荡市容易产生假突破，可能会增加交易频率和磨损成本。 |
| 📉 单边暴跌 | ★★☆☆☆ (较差) | 虽然策略有 BTC 趋势过滤和止损机制，但由于 NFI 本质是一个**趋势策略**，在突发性暴跌（如 312、519 事件）中，流动性枯竭可能导致止损滑点过大。不过，其"多条件过滤"机制能帮助它在暴跌初期就停止开新单，避免"抄底抄在半山腰"。 |
| ⚡️ 极端横盘 | ★☆☆☆☆ (极差) | 当市场波动率极低，且无明显趋势时，NFI 的多数买入条件将无法触发（未达到技术指标阈值）。此时策略会处于"休眠"状态，资金利用率较低。 |

### 9.3 关键配置建议

要想跑好这个策略，不能直接开箱即用，需要遵循开发者的建议：

| 配置项 | 建议值 | 说明 |
|--------|--------|------|
| **交易对数量** | 40-80 个 USDT 交易对 | 如 BTC/USDT, ETH/USDT 等，不要配 BTC 或 ETH 作为计价币种的交易对 |
| **最大持仓数** | 4-12 个订单 | `max_open_trades` 建议设为 4-12 |
| **仓位模式** | 全仓模式 | `stake_amount: unlimited` |
| **时间框架** | 5m | 强制要求，不可更改 |
| **卖出信号** | `use_exit_signal: true` | 使用策略的自定义卖出信号 |
| **仅盈利退出** | `exit_profit_only: false` | 即使未盈利，如果卖出信号出现也要卖，用于及时止损 |
| **忽略 ROI** | `ignore_roi_if_entry_signal: true` | 如果出现卖出信号，忽略预设的 ROI 止盈表 |

## 十、重要提醒：复杂性的代价

### 10.1 学习成本极高

这个策略几乎没办法通过修改几个参数来微调。如果你没有 Python 基础，很难理解其复杂的逻辑嵌套。

### 10.2 硬件要求

由于要计算 40-80 个交易对的多重指标，对 VPS 内存要求较高。官方建议至少 **4GB 内存**，否则可能因计算超时而导致运行卡顿。

| 交易对数量 | 最低内存 | 推荐内存 |
|-----------|---------|---------|
| 20-40 对 | 2GB | 4GB |
| 40-80 对 | 4GB | 8GB |
| 80+ 对 | 8GB | 16GB |

### 10.3 回测与实盘的差异

NFI 包含动态调仓和 Hold Support 功能，这些逻辑在普通回测中难以完全模拟。建议先使用模拟交易（Dry-Run）运行 1-3 个月，观察实盘表现后再考虑投入真金白银。

### 10.4 手动交易者建议

如果你是手动交易者，NFI 适合在**大盘站上 MA20 且均线多头排列**时开启；如果你是全自动运行，建议开启**比特币趋势过滤**功能，这样在大盘走熊时它能帮你自动"躺平"防守。

## 十一、总结

**Nostalgia** 是一个设计精良的多策略融合系统，它的核心价值在于：

1. **模块化设计**：31 个买入条件如同 31 个独立策略，可根据市场状态灵活组合
2. **风险优先**：多层保护机制确保在极端行情下的资金安全
3. **经典传承**：融合了数十年来被验证有效的技术分析指标
4. **现代适配**：兼容 Freqtrade v3 接口，可直接部署

对于量化交易者而言，这是一个值得深入研究的策略模板。建议：
- 先使用少量条件进行回测验证
- 根据目标交易对特性调整保护参数
- 关注 1h 时间框架的趋势确认信号
- 定期评估各买入条件的贡献度，优化组合
