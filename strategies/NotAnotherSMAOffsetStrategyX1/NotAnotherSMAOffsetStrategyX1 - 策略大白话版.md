## 1. 这个策略是干啥的？

### 一句话解释

NotAnotherSMAOffsetStrategyX1 是一个"低买高卖"的量化交易策略，专门用来炒币（加密货币交易）。

### 它是怎么来的？

这个名字挺有意思，"NotAnother"翻译过来就是"不是又一个"，意思大概是"我不是那种普通的移动平均线策略"。确实，这个策略不是简单地看金叉死叉就买卖，而是有一套更聪明的办法。

### 核心思路

想象你在超市买菜。你不会不管价格多少都买，而是会等菜价便宜了再买，贵了就卖。这个策略就是这个思路：

1. **等便宜**：当价格跌到比"正常价"还低的时候，再买入
2. **等贵了**：当价格涨到比"正常价"还高的时候，再卖出
3. **看趋势**：不是所有便宜都买，要看现在是大趋势向上还是向下
4. **控制风险**：买了以后要是亏太多，就及时止损

### 它适合谁？

- **适合**：喜欢短线交易的人、想自动化交易的人、能接受一定风险的人
- **不适合**：想一夜暴富的人、完全不懂技术分析的人、承受不了亏损的人

### 它能赚多少？

这个问题没标准答案。就像问"炒股能赚多少"一样，取决于很多因素：市场行情好不好、参数调得对不对、你有没有严格执行策略。一般来说，年化收益 20%-50% 是比较合理的预期，但也可能亏钱。

## 2. 准备工作：需要哪些工具？

### 硬件要求

**电脑**：
- 最好是 Linux 系统（Ubuntu 20.04 以上）
- 内存至少 8GB，推荐 16GB
- CPU 四核以上
- 硬盘空间 50GB 以上（要存历史数据）

**网络**：
- 稳定的网络连接，延迟最好低于 100ms
- 如果用国外交易所，需要稳定的代理

### 软件要求

**核心软件**：
- Python 3.8 以上
- Freqtrade（量化交易框架）
- TA-Lib（技术分析库）
- pandas（数据处理库）

**安装步骤**：
```bash
# 安装 Freqtrade
pip install freqtrade

# 安装 TA-Lib
pip install TA-Lib

# 下载策略文件
git clone [策略仓库地址]

# 把策略文件放到 Freqtrade 的 strategies 目录下
```

### 数据准备

回测和实盘都需要历史数据：

```bash
# 下载历史数据（以 BTC/USDT 为例）
freqtrade download-data --exchange binance --pairs BTC/USDT --timeframes 5m --timerange 20230101-
```

你需要准备一个 `config.json` 文件，里面写好：

- 交易所 API 密钥

- 最大同时持仓数
- 其他设置

- **最小资金**：$500（更少的话，手续费占比太高）
- **推荐资金**：$2000-$10000
- **风险资金**：不要超过你能承受损失的金额

## 3. 核心指标：看懂这些就够了

别被代码里的那些指标吓到了，其实只要理解几个核心的就行。

### 移动平均线（MA/EMA）

**简单理解**：就是把最近几根 K 线的价格平均一下，画成一条平滑的线。

策略用两种移动平均线：

1. **EMA 14**（买入参考线）：14 根 K 线的平均价，反应快
2. **EMA 24**（卖出参考线）：24 根 K 线的平均价，反应慢

**为什么要两个？**
- 买入时用快线（14）：想早点发现机会
- 卖出时用慢线（24）：不想过早离场，让利润多跑一会儿

### 赫尔移动平均线（HMA）

**简单理解**：一种更"聪明"的移动平均线，反应快但又不抖动。

策略用的是 HMA 50，用来判断中期趋势：
- 价格在 HMA 50 之上：中期趋势向上
- 价格在 HMA 50 之下：中期趋势向下

### 艾略特波浪振荡器（EWO）

**简单理解**：测量"快线"和"慢线"之间的距离，判断趋势强不强。

这个指标有点复杂，但用法很简单：
- **EWO 大于 2.327**：趋势很强，向上冲
- **EWO 小于 -19.988**：趋势很弱，向下跌

策略用这个指标来区分两种买入机会：
1. 在上升趋势中买回调（EWO 高的时候）
2. 在下跌到底后买反弹（EWO 低的时候）

### 相对强弱指数（RSI）

**简单理解**：测量价格涨跌的速度和幅度，判断是不是涨太多或跌太多。

策略用三个 RSI：

1. **RSI 4（快速）**：4 根 K 线算的，反应特别快
   - 用来判断短期是不是跌太快了（RSI < 35 就算跌多了）
   
2. **RSI 14（标准）**：14 根 K 线算的，经典配置
   - 用来判断整体是不是偏高（RSI < 69 才考虑买）
   
3. **RSI 20（慢速）**：20 根 K 线算的，反应慢
   - 用来判断短期动量是不是比中期强（RSI 4 > RSI 20 才卖）

**记住**：
- RSI < 30：超卖，可能要反弹
- RSI > 70：超买，可能要回调
- 策略用的阈值（35、69）稍微宽松一点

### 成交量（Volume）

**简单理解**：有多少人在买卖。

策略只用了一个简单条件：`volume > 0`。意思是只要有成交就行，不要求成交量特别大。这个设置比较宽松，避免错过机会。

## 4. 买入信号：什么时候该出手？

策略有**两种买入信号**，我们一个一个讲。

### 信号 1：ewo1（趋势回调买入）

这是最主要的买入信号，大概占 80% 的交易。

**触发条件**：

```
1. RSI 4 < 35        （短期内跌得有点多）
2. 价格 < EMA 14 × 0.975   （价格比均线低 2.5%）
3. EWO > 2.327       （大趋势还是向上的）
4. RSI 14 < 69       （整体还没涨太多）
5. 成交量 > 0        （有人交易）
6. 价格 < EMA 24 × 0.991 （还有一个安全阀）
```

**用人话说就是**：

"现在价格比平时便宜了（条件 2、6），短期内跌得比较急（条件 1），但大趋势还是向上的（条件 3），整体也没涨太多（条件 4），而且有人交易（条件 5）——可以买！"

**为什么这样设计？**

想象你在高速公路上开车。虽然偶尔要减速（回调），但只要大方向是对的（EWO 高），减速反而是超车的机会。这个信号就是抓住上升趋势中的回调机会。

### 信号 2：ewolow（抄底买入）

这是逆向买入信号，只在市场极度悲观时触发。

**触发条件**：

```
1. RSI 4 < 35        （短期内跌得有点多）
2. 价格 < EMA 14 × 0.975   （价格比均线低 2.5%）
3. EWO < -19.988     （大趋势跌得很惨）
4. 成交量 > 0        （有人交易）
5. 价格 < EMA 24 × 0.991 （还有一个安全阀）
```

**用人话说就是**：

"现在价格比平时便宜了（条件 2、5），短期内跌得比较急（条件 1），大趋势跌得很惨（条件 3），已经跌到可能到底了——抄底的机会来了！"

**为什么这样设计？**

市场有时候会跌过头，大家恐慌抛售。这时候反而可能是机会。就像股票大跌后经常会有反弹，这个信号就是抓住这种"跌过头"的机会。

### 注意事项

1. **ewo1 和 ewolow 不会同时触发**：因为 EWO 不可能同时大于 2.327 又小于 -19.988
2. **ewolow 触发次数少**：默认参数下很少触发，因为 EWO 要跌到 -19.988 真的很难
3. **成交量条件最宽松**：只要有成交就行，不要求放量

### 买入信号示例

假设 BTC 现在的价格情况：

```
当前价格：$50,000
EMA 14：$51,282（所以价格是均线的 97.5%）
EMA 24：$50,459
RSI 4：30
RSI 14：55
EWO：3.5
成交量：有

判断：
✓ RSI 4 = 30 < 35
✓ 价格 = $50,000 < $51,282 × 0.975 = $50,000 ✓（刚好满足）
✓ EWO = 3.5 > 2.327
✓ RSI 14 = 55 < 69
✓ 成交量 > 0
✓ 价格 = $50,000 < $50,459 × 0.991 = $50,004 ✓

结论：触发 ewo1 买入信号！
```

## 5. 卖出信号：什么时候该撤退？

卖出比买入复杂一点，因为要考虑更多情况。

### 卖出条件

策略根据价格相对于 HMA 50 的位置，有两种卖出条件。

**情况 1：价格在 HMA 50 之上（趋势向上）**

```
1. 价格 > HMA 50       （确认趋势向上）
2. 价格 > EMA 24 × 0.997 （价格比均线高 0.3%）
3. RSI 14 > 50        （不是超卖）
4. RSI 4 > RSI 20     （短期动量强于中期）
5. 成交量 > 0         （有人交易）
```

**用人话说**：

"价格已经在中期均线之上，而且比均线高了一点点，动量还在加速——该卖了。"

**情况 2：价格在 HMA 50 之下（趋势走弱）**

```
1. 价格 < HMA 50       （趋势可能走弱）
2. 价格 > EMA 24 × 0.991 （价格比均线高 0.9%）
3. RSI 4 > RSI 20     （短期动量强于中期）
4. 成交量 > 0         （有人交易）
```

**用人话说**：

"价格已经跌到中期均线以下，虽然现在比均线高了一点点，但趋势不太妙——赶紧卖。"

### 为什么分两种情况？

聪明的地方来了：

- **趋势向上时（情况 1）**：卖出条件更严格（high_offset_2 = 0.997），要等价格更高才卖
- **趋势走弱时（情况 2）**：卖出条件更宽松（high_offset = 0.991），价格稍微高一点就卖

这就像开车：
- 路况好（趋势向上）：慢慢开，多走一会儿
- 路况差（趋势走弱）：赶紧找出口，别耽误

### 还有最后一道关：卖出确认

即使触发了卖出信号，策略还会再检查一次：

```python
if (HMA 50 > EMA 100 × 1.149) and (价格 < EMA 100 × 0.951):
    不卖！
```

**用人话说**：

"如果中期趋势还是向上的（HMA 50 比长期均线 EMA 100 高很多），但价格暂时跌得比较深——那先别急着卖，可能还会涨回来。"

这是为了防止在上涨途中的深度回调时恐慌性卖出。

### 卖出信号示例

假设 BTC 现在的情况：

```
当前价格：$52,000
HMA 50：$51,000
EMA 24：$51,952
RSI 14：55
RSI 4：58
RSI 20：50
成交量：有

判断：
✓ 价格 = $52,000 > HMA 50 = $51,000
✓ 价格 = $52,000 > EMA 24 × 0.997 = $51,796 ✓
✓ RSI 14 = 55 > 50
✓ RSI 4 = 58 > RSI 20 = 50
✓ 成交量 > 0

结论：触发卖出信号！

再检查卖出确认：
假设 HMA 50 = $51,000，EMA 100 = $49,000
HMA 50 × 1.149 = $58,599 > EMA 100 = $49,000 ✓（趋势向上）
价格 = $52,000 > EMA 100 × 0.951 = $46,599 ✓（价格没跌太深）

结论：可以卖出！
```

## 6. 止损保护：怎么控制风险？

策略有**五层保护**，就像洋葱一样一层一层包着。

### 第一层：硬止损（最后防线）

```python
stoploss = -0.35
```

**意思**：一笔交易最多亏 35%。

这是最后防线，只有其他止损都失效了才会触发。就像保险柜的最后一把锁，平时用不到，但必须有。

### 第二层：追踪止损（跟着价格走）

```python
trailing_stop = True
trailing_stop_positive = 0.005
trailing_stop_positive_offset = 0.03
trailing_only_offset_is_reached = True
```

**用人话说**：

1. 等你赚了 3% 后（trailing_stop_positive_offset = 0.03）
2. 开始启动"保镖"（追踪止损）
3. 保镖会在最高价下面 0.5% 的地方（trailing_stop_positive = 0.005）
4. 价格涨，保镖跟着涨；价格跌到保镖的位置，就卖出

**举个例子**：

```
买入价：$50,000
涨到 $51,500（赚了 3%）→ 启动追踪止损
涨到 $52,000 → 止损线在 $51,740（$52,000 × 99.5%）
涨到 $53,000 → 止损线在 $52,735（$53,000 × 99.5%）
跌到 $52,735 → 触发止损，卖出！
实际赚了：($52,735 - $50,000) / $50,000 = 5.47%
```

### 第三层：自定义止损（分段保护）

这个最复杂，但最聪明。

```python
利润 < 2.2%：用硬止损（比如亏 8%）
利润 2.2% ~ 8%：止损线随利润增加
利润 > 8%：止损线紧贴利润
```

**分段解释**：

**阶段 1：刚买入，利润还不多（< 2.2%）**

止损线在开仓价下面 8% 左右。这时候给价格比较大的活动空间，别因为小波动就被洗出去。

**阶段 2：利润开始增加（2.2% ~ 8%）**

止损线开始往上移，但移得不太快。比如利润 5% 时，止损线大概在开仓价上面 3%。

**阶段 3：利润很多了（> 8%）**

止损线紧跟着利润走。利润涨多少，止损线就跟着涨多少。比如利润 12%，止损线就在开仓价上面 8%。

**为什么要分三段？**

- **刚买时**：给价格活动空间，别太敏感
- **赚了一些**：开始保护利润，但还留点空间
- **赚很多了**：紧紧锁住利润，别让到手的鸭子飞了

### 第四层：ROI 目标（时间价值）

```python
ROI 表：
0 分钟：目标 21.5%（不现实，只是个上限）
40 分钟：目标 3.2%
87 分钟：目标 1.6%
201 分钟：目标 0%（可以平价出场）
```

**用人话说**：

"持仓时间越长，对利润的要求越低。"

这就像做生意：
- 刚开始，期望高回报
- 时间长了，只要有点利润就行
- 太久了，能回本也行，别砸手里

### 第五层：保护机制（熔断器）

```python
保护机制 1：LowProfitPairs
- 回看 60 根 K 线（300 分钟 = 5 小时）
- 如果某个币亏了超过 5%
- 暂停交易这个币 60 分钟

保护机制 2：CooldownPeriod
- 每笔交易后
- 强制休息 2 根 K 线（10 分钟）
```

**用人话说**：

- **LowProfitPairs**：某个币让你亏钱了，先别碰它，冷静一会儿
- **CooldownPeriod**：刚交易完，别急着下一笔，休息一会儿

### 五层保护的总结

```
第 1 层：硬止损（35%）      → 最后防线，很少触发
第 2 层：追踪止损（0.5%）    → 赚了 3% 后启动，跟着价格走
第 3 层：自定义止损（分段）  → 根据利润动态调整
第 4 层：ROI 目标           → 根据时间调整期望
第 5 层：保护机制           → 连续亏损后暂停
```

实际运行时，通常是第 2 层或第 3 层触发最多，第 1 层几乎不会触发。

## 7. 参数调整：怎么优化策略？

策略有很多参数可以调，但**别乱调**，调错了可能更差。

### 主要参数一览

**买入相关**：

| 参数 | 默认值 | 范围 | 作用 |
|------|--------|------|------|
| base_nb_candles_buy | 14 | 5-80 | 买入均线周期 |
| low_offset | 0.975 | 0.90-0.99 | 买入价格偏移 |
| ewo_high | 2.327 | 2.0-12.0 | 趋势确认阈值 |
| ewo_low | -19.988 | -20.0~-8.0 | 抄底确认阈值 |
| rsi_buy | 69 | 30-70 | RSI 买入阈值 |

**卖出相关**：

| 参数 | 默认值 | 范围 | 作用 |
|------|--------|------|------|
| base_nb_candles_sell | 24 | 5-80 | 卖出均线周期 |
| high_offset | 0.991 | 0.95-1.1 | 卖出价格偏移 1 |
| high_offset_2 | 0.997 | 0.99-1.5 | 卖出价格偏移 2 |

**止损相关**：

| 参数 | 默认值 | 作用 |
|------|--------|------|
| pHSL | -0.08 | 硬止损利润 |
| pPF_1 | 0.022 | 利润阈值 1（2.2%） |
| pSL_1 | 0.021 | 止损级别 1（2.1%） |
| pPF_2 | 0.08 | 利润阈值 2（8%） |
| pSL_2 | 0.04 | 止损级别 2（4%） |

### 哪些参数最值得调？

**优先级 1（影响最大）**：

- **low_offset**：决定在什么价位买入。调小 → 买得更便宜，但机会少；调大 → 买入更早，但可能被套
- **high_offset 和 high_offset_2**：决定在什么价位卖出。调大 → 卖得更高，但可能错过；调小 → 卖得更早，可能少赚

**优先级 2（影响中等）**：

- **ewo_high 和 ewo_low**：决定趋势判断的严格程度。调大 ewo_high → 更严格的趋势确认；调小 ewo_low（更负）→ 更严格的抄底条件
- **base_nb_candles_buy 和 base_nb_candles_sell**：决定均线周期。调小 → 更敏感，信号多；调大 → 更平滑，信号少

**优先级 3（影响较小）**：

- **止损参数**：已经优化过，不太需要调
- **rsi_buy**：影响较小，因为本来就很宽松

### 怎么优化参数？

**方法 1：Hyperopt 自动优化**

Freqtrade 提供了 Hyperopt 工具，可以自动找最优参数：

```bash
# 只优化买入参数
freqtrade hyperopt --strategy NotAnotherSMAOffsetStrategyX1 --spaces buy --epochs 100

# 只优化卖出参数
freqtrade hyperopt --strategy NotAnotherSMAOffsetStrategyX1 --spaces sell --epochs 100

# 优化所有参数
freqtrade hyperopt --strategy NotAnotherSMAOffsetStrategyX1 --spaces buy sell roi stoploss --epochs 500
```

**方法 2：手动调参**

基于经验和直觉：

1. 如果交易次数太少：调大 low_offset，降低 ewo_high
2. 如果交易次数太多：调小 low_offset，提高 ewo_high
3. 如果卖出太早：调大 high_offset_2
4. 如果止损太多：调小 pHSL（更负的值）

**重要提醒**：

- **不要过度优化**：在某个时期表现最好的参数，可能只是"运气好"，换个时期就不行了
- **用多个交易对测试**：如果一个参数对所有交易对都有效，那才是真的好
- **留验证集**：用 70% 的数据优化，用 30% 的数据验证

### 参数调优示例

## 8. 时间周期：用哪个时间框架？

### 默认设置

```python
timeframe = '5m'  # 5 分钟 K 线
inf_1h = '1h'     # 1 小时 K 线（备用）
```

### 5 分钟时间框架的特点

**优点**：

- 信号多：每天有 288 根 K 线，机会多
- 反应快：能快速捕捉价格变化
- 适合短线：持仓时间 1-8 小时

**缺点**：

- 噪音多：假信号相对多
- 对网络要求高：需要快速响应
- 手续费占比高：交易频繁，手续费多

### 其他时间框架的选择

**1 分钟（1m）**：

- 信号特别多，但噪音也特别多
- 需要极快的网络和服务器
- 一般不推荐

**15 分钟（15m）**：

- 信号适中，噪音较少
- 持仓时间更长（几小时到几天）
- 适合兼职交易者

**1 小时（1h）**：

- 信号少，但质量高
- 持仓时间更长（几天到一周）
- 适合趋势交易

### 时间框架调整建议

**从 5 分钟改成 15 分钟**：

```python
timeframe = '15m'
inf_1h = '4h'
startup_candle_count = 200  # 适当减少
```

**需要同时调整的参数**：

1. ROI 表的时间翻倍（40 → 120，87 → 261，201 → 603）
2. 均线周期可以适当减小（14 → 10，24 → 16）
3. EWO 周期需要调整（50 → 16，200 → 67，大约除以 3）

**注意**：改时间框架相当于改了整个策略，必须重新回测和优化参数！

## 9. 优缺点分析：值不值得用？

### 优点

**1. 思路清晰**

策略逻辑很清楚：价格便宜时买，价格贵时卖，再加上趋势判断。不像有些策略逻辑很复杂，连作者自己都解释不清楚。

**2. 风险控制完善**

五层保护机制，很难出现巨亏。追踪止损和自定义止损能很好地保护利润。

**3. 参数可调**

所有关键参数都可以调整和优化，可以根据不同的交易对和市场环境定制。

**4. 代码质量高**

结构清晰，注释充分，容易理解和修改。

**5. 双轨买入机制**

既有顺势买入（ewo1），又有逆向买入（ewolow），能适应不同市场环境。

### 缺点

**1. 趋势依赖**

在明显的趋势行情中表现好，但在震荡或趋势反转时可能表现不佳。

**2. 参数敏感**

参数很多，优化空间大，但也容易过拟合（在历史数据表现好，实盘表现差）。

**3. 只用了 5 分钟框架**

虽然定义了 1 小时框架，但没有实际使用，错过了大周期趋势确认。

**4. 没有成交量分析**

只检查成交量大于 0，没有利用成交量信息判断市场关注度。

**5. 对极端行情应对不足**

在快速暴涨暴跌时，可能来不及反应。

### 适合的市场环境

| 市场环境 | 表现 | 原因 |
|---------|------|------|
| 上升趋势 | 优秀 | ewo1 信号能抓住回调机会 |
| 下降趋势 | 较差 | 抄底信号（ewolow）很难触发 |
| 震荡上涨 | 良好 | 均值回归策略的优势场景 |
| 震荡下跌 | 一般 | 可能频繁止损 |
| 横盘震荡 | 一般 | 信号少，盈利空间小 |
| 剧烈波动 | 较差 | 来不及反应 |

### 不适合的情况

- 完全新手，不懂技术分析
- 想完全"躺赚"，不想学习
- 资金很少（< $500）
- 无法承受 20% 以上的回撤
- 在极端行情时期（如政策重大利空）

## 12. 常见问题：有疑惑看这里

### Q1：为什么我的回测结果很好，但实盘亏损？

**原因**：

1. **过拟合**：参数针对历史数据优化，换个时期就不行了
2. **滑点**：回测假设完美成交，实盘有滑点
3. **手续费**：回测可能低估了手续费影响
4. **市场变化**：市场环境变了，策略不再适用

**解决**：

- 用多个时期的数据回测
- 用多个交易对验证
- 适当降低预期收益
- 实盘先用小资金测试

### Q2：信号太少，几个月才几笔交易，怎么办？

**原因**：

- low_offset 太严格（比如 0.95）
- ewo_high 太高
- 交易对选择不合适（波动太小）

**解决**：

- 调大 low_offset（比如 0.985）
- 降低 ewo_high（比如 1.5）
- 选择波动大的交易对
- 增加交易对数量

### Q3：信号太多，一天几十笔，怎么办？

**原因**：

- low_offset 太宽松（比如 0.99）
- ewo_high 太低
- 时间框架太小（1 分钟）

**解决**：

- 调小 low_offset（比如 0.965）
- 提高 ewo_high（比如 3.0）
- 增加时间框架（15 分钟或 1 小时）
- 增加过滤条件（如 RSI < 60）

### Q4：止损太多，胜率太低，怎么办？

**原因**：

- 买入太早，还没到底就买了
- 卖出太晚，错过了高点
- 止损设置太紧

**解决**：

- 调小 low_offset（买得更便宜）
- 调小 high_offset_2（卖得更早）
- 放宽自定义止损参数

### Q5：最大回撤太大，承受不了，怎么办？

**原因**：

- 同时持仓太多
- 单笔金额太大
- 止损不够严格

**解决**：

- 减少最大持仓数（max_open_trades = 2）
- 减少单笔金额（stake_amount = 100）
- 调紧止损参数

### Q6：能用在股票或外汇吗？

**回答**：

理论上可以，但需要调整：

- **股票**：不能 24 小时交易，时间框架需要调整；没有加密货币波动大
- **外汇**：可以尝试，但波动和手续费结构不同

**建议**：

先在加密货币上验证策略，如果表现稳定，再考虑移植到其他市场。

### Q7：参数优化要多久？

**回答**：

取决于：

- 优化范围（buy/sell/roi/stoploss）
- 优化轮数（epochs）
- 数据量
- 电脑性能

**参考时间**：

- 单一空间（buy 或 sell）100 轮：几分钟
- 所有空间 500 轮：几十分钟到几小时

### Q8：怎么知道参数不过拟合？

**方法**：

1. **多时期验证**：用 2022 年数据优化，用 2023 年数据验证
2. **多交易对验证**：用 BTC 优化，在 ETH 上测试
3. **参数稳定性**：如果最优参数是 0.975，但 0.974 和 0.976 表现差很多，说明不稳定
4. **简化参数**：参数越少越不容易过拟合
