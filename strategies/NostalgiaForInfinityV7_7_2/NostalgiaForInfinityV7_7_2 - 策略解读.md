## 一、策略概览

NostalgiaForInfinityV7_7_2 是 NostalgiaForInfinity 系列策略的一个重要版本，由 iterativ 团队开发维护。该策略继承了系列标志性的复杂架构设计，通过大量精心设计的买入条件、严密的保护机制和多层级的卖出逻辑，构建了一个高度防御性的趋势跟踪交易系统。

作为 Freqtrade 生态中最知名的开源策略之一，NostalgiaForInfinity 系列以其"条件多到令人发指"的特点闻名，V7_7_2 版本延续了这一传统，包含 44 个独立买入条件和 8 个基础卖出条件，配合高度复杂的自定义卖出逻辑，旨在捕捉加密货币市场中的趋势机会，同时尽可能降低错误信号的伤害。

### 核心特征

| 特征 | 描述 |
|------|------|
| **买入条件** | 44 个独立买入信号，全部可独立启用/禁用 |
| **卖出条件** | 8 个基础卖出信号 + 多层动态止盈逻辑（分级止盈、追踪止盈、特殊场景退出） |
| **保护机制** | 44 组买入保护参数（EMA 趋势、SMA 上升趋势、安全下跌、安全上涨、BTC 趋势过滤等） |
| **时间框架** | 主时间框架 5m，信息时间框架 1h，可选 BTC 参考时间框架 |
| **依赖库** | pandas_ta（必须），talib，technical |
| **止损设置** | 静态止损 -10%，追踪止损 +1%（需上涨 3% 后激活） |

## 二、策略配置解析

### 2.1 基础风险参数

```python
# ROI 退出表
minimal_roi = {
    "0": 0.10,   # 立即获利 10%
    "30": 0.05,  # 30 分钟后获利 5%
    "60": 0.02,  # 60 分钟后获利 2%
}

# 止损设置
stoploss = -0.10  # 10% 止损

# 追踪止损
trailing_stop = True
trailing_only_offset_is_reached = True
trailing_stop_positive = 0.01       # 追踪止损 1%
trailing_stop_positive_offset = 0.03  # 需先盈利 3% 才激活
```

**设计思路**：
- ROI 表设置相对宽松，实际退出主要依赖自定义卖出逻辑
- 止损设为 -10%，为波动性较大的加密货币预留足够空间
- 追踪止损采用"先盈利后追踪"设计，避免在震荡中被过早止损
- 实际交易中，自定义卖出逻辑（custom_sell）承担主要的止盈止损功能

### 2.2 订单类型配置

```python
order_types = {
    'buy': 'limit',
    'sell': 'limit',
    'trailing_stop_loss': 'limit',
    'stoploss': 'limit',
    'stoploss_on_exchange': False
}
```

所有订单均使用限价单，确保在流动性充足时获得更好的成交价格。

### 2.3 启动期设置

```python

```

策略需要大量历史数据来计算各类技术指标，尤其是 480 周期的 Williams %R 和长周期 EMA。

## 三、买入条件详解

### 3.1 保护机制（44 组）

NostalgiaForInfinityV7_7_2 的核心特色在于每个买入条件都配有一套独立的保护参数组，这些参数共同构成了策略的"防御层"。44 组保护参数覆盖了从激进到保守的各种组合。

每个保护参数组包含以下配置项：

| 保护类型 | 参数名称 | 说明 |
|---------|---------|------|
| **EMA 快速趋势** | `ema_fast` | 检查快速 EMA 是否在 EMA200 之上 |
| **EMA 慢速趋势** | `ema_slow` | 检查 1h 时间框架的慢速 EMA 是否在 EMA200 之上 |
| **价格位置快速** | `close_above_ema_fast` | 收盘价需在指定 EMA 之上 |
| **价格位置慢速** | `close_above_ema_slow` | 收盘价需在 1h 时间框架指定 EMA 之上 |
| **SMA200 上升** | `sma200_rising` | SMA200 在指定周期内处于上升状态 |
| **SMA200_1h 上升** | `sma200_1h_rising` | 1h 时间框架的 SMA200 处于上升状态 |
| **安全下跌** | `safe_dips` | 防止在深度下跌时买入（多级阈值） |
| **安全上涨** | `safe_pump` | 防止在暴涨后追高（多级阈值） |
| **BTC 趋势过滤** | `btc_1h_not_downtrend` | BTC 在 1h 时间框架不是下跌趋势时才买入 |

### 3.2 安全下跌/上涨阈值系统

策略定义了 13 级下跌阈值和上涨阈值，从最保守的 Level 10 到最激进的 Level 130：

**下跌阈值（safe_dips）示例**：
```python
# 严格级别 - Level 10
buy_dip_threshold_10_1 = 0.015  # 当前价格不能低于近期最低点 1.5%
buy_dip_threshold_10_2 = 0.1    # 2 周期内最大跌幅 10%
buy_dip_threshold_10_3 = 0.24   # 12 周期内最大跌幅 24%
buy_dip_threshold_10_4 = 0.42   # 144 周期内最大跌幅 42%

# 宽松级别 - Level 130
buy_dip_threshold_130_1 = 0.028
buy_dip_threshold_130_2 = 0.3
buy_dip_threshold_130_3 = 0.48
buy_dip_threshold_130_4 = 0.9   # 允许 90% 的跌幅
```

**上涨阈值（safe_pump）示例**：
```python
# 24 小时级别 - Level 10
buy_pump_pull_threshold_10_24 = 2.2  # 回撤比例阈值
buy_pump_threshold_10_24 = 0.42      # 24 小时最大涨幅 42%

# 48 小时级别 - Level 120
buy_pump_threshold_120_48 = 2.0      # 48 小时最大涨幅 200%
```

## 六、风险管理特色

### 6.1 多层保护过滤器

每个买入信号都必须通过保护参数的检验，形成层层过滤：

**第一层：趋势过滤器**
```python
# 示例：条件 1
ema_slow: True  → EMA100_1h > EMA200_1h（中期趋势向上）
sma200_rising: True  → SMA200 在 28 周期内上升（长期趋势向上）
```

**第二层：价格位置过滤器**
```python
# 示例：条件 8
close_above_ema_fast: True  → 收盘价 > EMA200
```

### ✅ 优势

4. **回测与实盘差异**：复杂逻辑在回测中表现优异，实盘可能因滑点、延迟等因素表现不同

## 九、适用市场环境详解

NostalgiaForInfinityV7_7_2 是典型的"防御型趋势跟踪策略"。基于其代码架构和社区长期实盘验证的经验，它最适合 **稳定上涨的中等波动市场**，而在 **极端单边下跌** 或 **低波动横盘** 时表现不佳。

### 9.1 策略核心逻辑

- **趋势优先**：大多数买入条件都要求 EMA 排列向上或 SMA200 上升
- **回调入场**：等待 RSI、CTI、价格等指标回调到超卖区域才入场
- **保护层层叠加**：每个信号都要通过趋势、位置、下跌、上涨、BTC 趋势等多层检验
- **止盈动态调整**：根据利润率、RSI、市场状态（多头/空头/Pump）决定止盈点

### 9.2 不同市场环境表现

| 市场类型 | 表现评级 | 原因分析 |
| :--- | :--- | :--- |
| 📈 慢牛/稳定上涨 | ⭐⭐⭐⭐⭐ | 趋势条件满足，回调入场效果最佳 |
| 🔄 中等波动震荡 | ⭐⭐⭐⭐☆ | 布林带条件可捕捉波动机会 |
| 📉 单边下跌 | ⭐⭐☆☆☆ | 保护机制会大幅减少交易，但可能错过超跌反弹 |
| ⚡️ 极端暴涨 | ⭐☆☆☆☆ | safe_pump 会阻止追高，但可能错过强势币 |
| 😴 低波动横盘 | ⭐⭐☆☆☆ | 信号稀少，资金利用率低 |
