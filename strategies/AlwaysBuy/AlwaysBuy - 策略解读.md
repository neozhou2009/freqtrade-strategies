## 一、策略概览

AlwaysBuy 是一个极简策略，其核心设计理念是"无条件买入"。该策略没有技术指标分析，买入条件永远为真，主要用于测试框架功能、验证交易所连接、或作为其他策略的基准对照。

### 核心特征

| 特征 | 描述 |
|------|------|
| **买入条件** | 1 个（无条件触发） |
| **卖出条件** | 无主动卖出信号，依赖 ROI 和止损 |
| **保护机制** | 追踪止损 |
| **时间框架** | 5 分钟 (5m) |
| **依赖库** | 无（仅基础 freqtrade 库） |

## 二、策略配置解析

### 2.1 基础风险参数

```python
# ROI 退出表
minimal_roi = {
    "0": 1,      # 0 分钟后，100% 利润退出
    "100": 2,    # 100 分钟后，200% 利润退出
    "200": 3,    # 200 分钟后，300% 利润退出
    "300": -1    # 300 分钟后，禁用 ROI（-1 表示不退出）
}

# 止损设置
stoploss = -0.2  # 20% 固定止损
```

**设计思路**：
- ROI 表配置较为特殊，前三个条目设置了极高的利润目标（100%、200%、300%），实际交易中几乎不可能触及
- 最后一个条目 `-1` 表示在 300 分钟后禁用 ROI 退出，意味着完全依赖止损机制
- 这种配置表明该策略更像是一个测试框架，而非实际交易策略

### 2.2 追踪止损配置

```python
trailing_stop = True
trailing_stop_positive = 0.005     # 0.5% 利润后激活
trailing_stop_positive_offset = 0.03  # 3% 利润后开始追踪
trailing_only_offset_is_reached = True  # 仅在达到偏移后激活
```

**设计思路**：
- 追踪止损在利润达到 3% 时激活
- 激活后，回调 0.5% 即触发卖出
- 配置相对保守，适合低波动市场

### 2.3 订单类型配置

```python
use_exit_signal = False  # 禁用卖出信号
```

策略不使用任何卖出信号，完全依赖 ROI 和止损机制退出。

## 三、买入条件详解

### 3.1 唯一买入条件：无条件买入

```python
def populate_entry_trend(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
    dataframe.loc[:, ["enter_long", "enter_tag"]] = (1, "entry_reason")
    return dataframe
```

**逻辑分析**：
- 无任何条件判断
- 对所有 K 线标记为买入信号
- `enter_tag` 统一标记为 `"entry_reason"`

**实际效果**：
- 每根 K 线都会产生买入信号
- 在回测中，资金充足时会持续买入
- 在实盘中，受限于 `max_open_trades` 配置

## 七、策略优势与局限

### ✅ 优势

1. **极简设计**：代码量极少，便于理解和调试
2. **框架测试友好**：非常适合测试 Freqtrade 框架的各项功能
3. **基准对照价值**：可作为其他策略的对照组，评估技术分析的实际价值
4. **资源消耗低**：不计算任何指标，CPU 和内存占用最小

### ⚠️ 局限

1. **无交易逻辑**：不进行任何市场分析，纯随机交易
2. **风险敞口大**：无保护机制，可能连续亏损
3. **实际交易不可用**：ROI 配置不合理，止损过于宽松
4. **回测失真**：在回测中可能产生不切实际的交易频率

## 九、适用市场环境详解

AlwaysBuy 是一个**测试/基准策略**。它没有市场分析能力，不依赖任何技术指标，因此无法适应任何特定的市场环境。

### 9.1 策略核心逻辑

- **无条件买入**：不做任何判断，直接开仓
- **被动退出**：依赖止损和 ROI，无主动卖出
- **无保护机制**：没有风险管理层面的保护

### 9.2 不同市场环境表现

| 市场类型 | 表现评级 | 原因分析 |
| :--- | :--- | :--- |
| 📈 强趋势上涨 | ⭐⭐⭐☆☆ | 随机买入可能获利，但无趋势识别 |
| 🔄 震荡市场 | ⭐☆☆☆☆ | 频繁交易，手续费损耗严重 |
| 📉 下跌趋势 | ⭐☆☆☆☆ | 无止损保护外的风险规避 |
| ⚡️ 高波动 | ⭐⭐☆☆☆ | 可能被追踪止损频繁触发 |

### 9.3 关键配置建议

| 配置项 | 建议值 | 说明 |
|--------|--------|------|
| max_open_trades | 1-3 | 限制持仓数量，降低风险敞口 |

| dry_run | True | 强烈建议仅用于模拟测试 |

## 十、重要提醒：测试策略的本质

### 10.1 用途定位

AlwaysBuy 是一个**工具型策略**，而非交易策略：
- 用于测试 Freqtrade 框架功能
- 用于验证交易所 API 连接
- 用于作为策略开发的起点模板
- 用于对比评估其他策略的效果

### 10.2 不适合实盘

| 风险类型 | 说明 |
|---------|------|
| 无交易逻辑 | 买入完全随机，无任何分析依据 |
| 资金风险 | 可能产生大量无效交易，手续费损耗严重 |
| 止损过宽 | 20% 止损对大多数交易对来说过于宽松 |

### 10.3 正确使用方式

1. **框架测试**：验证 Freqtrade 安装正确性
2. **API 测试**：确认交易所连接和订单执行
3. **策略模板**：作为开发新策略的起点
4. **性能对比**：评估其他策略相对于"随机买入"的优势

---

## 十一、总结

**AlwaysBuy** 是一个极简的测试策略，其核心价值在于：

1. **框架验证**：快速验证 Freqtrade 安装和配置是否正确
2. **基准对照**：为评估其他策略提供"零技术分析"的参照
3. **学习模板**：展示 Freqtrade 策略的最小必需结构

对于量化交易者而言，该策略应仅用于测试和学习目的，**绝不应用于实盘交易**。如果需要简单的基准策略，建议考虑使用等权买入并持有的策略作为对比基准。
