## 一、这策略是个啥？

简单说，**NostalgiaForInfinityX2** 就是一个：

- 🎯 **趋势确认后等超卖**——先看大方向，再等回调，不追高
- 🔬 **多时间框架交叉验证**——5 分钟和 1 小时趋势必须一致，双重保险
- 💰 **26 级动态止盈**——利润越高，退出越积极，绝不吃回头草
- 🛡️ **四重安全防线**——硬止损 + 追踪止损 + 动态止盈 + 滑点保护

就像一个**老练的猎人**，不会看到猎物就开枪。先确认风向（趋势方向），再等猎物靠近到合适位置（超卖回调），最后稳稳拿下。🦌

**名字由来**：NostalgiaForInfinity 翻译过来就是"无限怀旧"，作者可能是在怀念 2017 年那种"买了就涨、涨了还涨"的美好时光吧！😂

## 二、核心配置：说白了就是"趋势来了再上车，赚够了就跑"

### 止盈规则（ROI 表）

```
立即      → 利润 10% 就撤
30 分钟后 → 利润 5% 就撤  
60 分钟后 → 利润 2% 就撤
```

**翻译**：持仓越久，止盈要求越低。啥意思？就是说——赚钱了就赶紧跑，别贪！刚买进去要是涨了 10%，立刻就跑。要是拿着超过半小时，涨 5% 也就够了。超过一小时？涨 2% 就撤！

这设计的潜台词是：**快进快出，落袋为安**。

### 止损规则

```
硬止损     → -10%（最后防线，亏到这就认输）
追踪止损   → 利润 3% 后激活，回撤 1% 就跑
紧急止损   → -5%（中间警告线，先撤退再说）
```

**翻译**：

- **亏到 5%**：嗯...情况不太对，先撤一部分吧
- **亏到 10%**：彻底认输，这单废了
- **赚了超过 3%**：开启"利润保护模式"，如果从最高点回撤 1%，立刻锁利走人

**举个例子**：买入后涨到 5% 利润，然后回调到 4%，这时候追踪止损就触发了，因为回撤了 1%！

### 订单类型

```python
order_types = {
    'buy': 'limit',   # 限价买入
    'sell': 'limit',  # 限价卖出
    'stoploss': 'limit',  # 止损也用限价
}
```

**翻译**：全用限价单，不用市价单。为啥？因为市价单可能滑点大，本来想 100 块买入，结果成交价 105，多花 5 块冤枉钱！

## 四、保护机制：滑点超过 3.8% 直接拒单

### 滑点保护

每次下单前，策略会检查实际价格和预期价格的差异：

| 滑点阈值 | 行为 |
|---------|------|
| < 3.8% | 允许交易 |
| ≥ 3.8% | 取消交易，发出警告 |

**大白话**：
> "咦？实际价格比预期高了 4%？这肯定有猫腻！流动性不足还是有人砸盘？不买了，撤！"

**吐槽**：这保护挺实用的。小币种拉盘的时候，滑点动不动就十几二十个点，有了这机制，至少不会被坑死。😅 不过 3.8% 也不算小了，正常情况应该在 1% 以内。

### 启动数据要求

```
startup_candle_count = 480  # 需要 480 根 5 分钟 K 线
```

**翻译**：策略启动需要大约 40 小时的历史数据，约 1.7 天。也就是说，刚上线的新币，策略可能不太好用——历史数据不够，均线算不准！

## 六、这策略的"人格特点"

### ✅ 优点（夸夸环节）

1. **趋势确认严谨**：双时间框架 SMA 验证，不逆势交易，宁缺毋滥
2. **止盈设计精妙**：26 级动态止盈，利润越高跑得越快，绝不吃回头草
3. **风险控制完备**：四重防线——硬止损、追踪止损、动态止盈、滑点保护
4. **计算效率高**：只在新 K 线计算指标，不浪费资源
5. **代码结构清晰**：按时间框架模块化，易读好维护
6. **入场价格好**：等超卖才进场，不追高

### ⚠️ 缺点（吐槽环节）

1. **买入条件太少**：就 1 个入场信号！机会不多，可能看着别人赚钱自己干瞪眼 🤷
2. **信息有点浪费**：BTC 数据和多时间框架指标算了一堆，但没全用上...作者是不是想以后再加？
3. **震荡市场吃力**：SMA 金叉过滤会阻止大部分入场，资金闲置在那儿
4. **对硬件有要求**：多时间框架数据加载，内存小了可能卡
5. **新币用不了**：需要 480 根历史 K 线，新上市的币没戏
6. **sell_long_bear 函数没实现**：代码里引用了这个函数，但函数体不存在...这是个 bug 吧？😅
