# Schism 策略深度解读

> **策略编号**: #375 (465 个策略中的第 375 个)  
> **策略类型**: 多条件趋势跟踪 + 动态止盈止损 + 实时仓位感知  
> **时间框架**: 5 分钟 (5m) + 1 小时信息层 (1h)

---

## 一、策略概览

Schism 是一个结合动量指标与趋势判断的中短期交易策略，核心特点在于"粘性买入信号"和"动态止损机制"。策略通过 RMI (相对动量指数) 的双时间框架分析，配合 Momentum Pinball 和 ADR (平均日波动范围) 定位，实现"抄底但不盲目抄底"的交易逻辑。

该策略由 @werkkrew 和 @JimmyNixx 开发，是 Schism 系列的基础版本，后续演化出 Schism2、Schism2MM 等进阶版本。

### 核心特征

| 特征 | 描述 |
|------|------|
| **买入条件** | 2 组独立买入信号（新仓位买入 + 持仓延续信号），支持 `ignore_roi_if_buy_signal` |
| **卖出条件** | 动态止损 + ROI 分级止盈，结合其他交易状态决策 |
| **保护机制** | 订单超时保护、入场确认、价格滑点保护 |
| **时间框架** | 主框架 5m + 信息框架 1h |
| **依赖库** | numpy, talib, qtpylib, arrow, pandas, technical.indicators.RMI, cachetools.TTLCache |

**设计思路**：

- `ignore_roi_if_buy_signal = True` 是策略核心，允许持仓延续信号覆盖 ROI

## 三、买入条件详解

### 3.1 技术指标体系

策略使用多维度指标组合：

| 指标类别 | 具体指标 | 参数 | 用途 |
|---------|---------|------|------|
| **动量指标** | RMI-slow | length=21, mom=5 | 趋势方向判断 |
| **动量指标** | RMI-fast | length=8, mom=4 | 快速信号捕捉 |
| **动量指标** | ROC | timeperiod=6 | 变化率测量 |
| **综合指标** | Momentum Pinball | RSI(ROC, 6) | 超买超卖定位 |
| **趋势指标** | RMI-up-trend | rolling(3) >= 2 | 上升趋势确认 |
| **趋势指标** | RMI-dn-trend | rolling(3) >= 2 | 下降趋势确认 |
| **信息层** | RSI_1h | timeperiod=14 | 高维度趋势判断 |
| **信息层** | 1d_high/3d_low | rolling(24/72) | 价格区间定位 |
| **信息层** | ADR | 1d_high - 3d_low | 波动范围计算 |

### 3.2 买入条件分类

策略根据是否存在活跃交易，使用不同的买入逻辑：

#### 条件组 #1：新仓位买入信号（无活跃交易时）

```python
# 核心逻辑
条件 = [
    RSI_1h >= 30,                                    # 1小时 RSI 不低于 30
    close <= 3d_low_1h + 0.8 * ADR_1h,              # 价格在 3 日低点上方 80% 波动范围
    rmi-dn-trend == 1,                               # RMI 下降趋势确认
    rmi-slow >= 20,                                  # 慢速 RMI 不低于 20
    rmi-fast <= 20,                                  # 快速 RMI 不高于 20
    mp <= 50,                                        # Momentum Pinball 不超过 50
    volume > 0                                       # 有成交量
]
```

**逻辑解读**：
- 信息层 RSI >= 30：确保不是极端超卖状态
- 价格定位：抄底但不抄在最低点，留出 80% 的波动空间
- RMI 配置：慢速 RMI >= 20（不极端弱势），快速 RMI <= 20（短期动量低迷）
- 趋势确认：RMI 下降趋势中寻找反转机会
- Momentum Pinball：等待动量企稳

#### 条件组 #2：持仓延续买入信号（有活跃交易时）

```python
# 核心逻辑 - 用于 ignore_roi_if_buy_signal 机制
条件 = [
    rmi-up-trend == 1,                               # RMI 上升趋势
    current_profit > peak_profit * profit_factor,    # 动态利润因子
    rmi-slow >= rmi_grow                             # RMI 动态增长阈值
]

# profit_factor 计算
profit_factor = 1 - (rmi-slow / 400)  # rmi 30 -> 0.925, rmi 80 -> 0.80

# rmi_grow 计算 (线性增长)
rmi_grow = linear_growth(30, 70, 180, 720, open_minutes)
# 从 30 增长到 70
# 开始时间：180 分钟后
# 结束时间：720 分钟后
```

**逻辑解读**：
- 趋势延续：RMI 上升趋势确认，防止过早卖出
- 动态利润因子：随着 RMI 升高，对利润要求降低（鼓励趋势持仓）
- 线性增长阈值：随着持仓时间增加，RMI 阈值逐渐提高，强制趋势确认

### 3.3 买入条件总结

| 条件组 | 适用场景 | 核心逻辑 |
|-------|---------|---------|
| 新仓位买入 | 无活跃交易 | 信息层定位 + RMI 逆势抄底 + 动量确认 |
| 持仓延续 | 有活跃交易 | 趋势确认 + 动态利润因子 + RMI 增长阈值 |

## 四、卖出逻辑详解

### 4.1 分级止盈系统（ROI）

策略采用时间递减 ROI 机制：

```
持仓时间      利润阈值    说明
────────────────────────────────
0 分钟        10%         极短期高利润目标
15 分钟       5%          快速止盈
30 分钟       2.5%        中期目标
60 分钟       1%          降低期望
120 分钟      0.5%        接受小利
1440 分钟     0%          接受任何利润
```

### 4.2 动态止损卖出

策略的卖出信号主要用于"动态止损"，而非主动止盈：

```python
# 动态止损条件
if active_trade:
    loss_cutoff = linear_growth(-0.03, 0, 0, 300, open_minutes)
    # 从 -3% 增长到 0%
    # 开始时间：立即
    # 结束时间：300 分钟后
    
    条件 = [
        current_profit < loss_cutoff,              # 利润低于动态阈值
        current_profit > stoploss,                 # 但未触及硬止损
        rmi-dn-trend == 1,                         # RMI 下降趋势
        volume > 0                                 # 有成交量
    ]
    
    # 利润状态分支
    if peak_profit > 0:
        条件 += [rmi-slow crossed_below 50]        # 曾盈利：RMI 下穿 50
    else:
        条件 += [rmi-slow crossed_below 10]        # 从未盈利：RMI 下穿 10
```

**逻辑解读**：
- 动态阈值：持仓时间越长，止损阈值越高（从 -3% 到 0%）
- 趋势确认：仅在下降趋势中触发，避免震荡市误卖
- 利润状态分支：曾盈利的交易使用更宽松的卖出条件（RMI 50），从未盈利的交易使用更严格条件（RMI 10）

### 4.3 其他交易状态感知

策略实现了全局仓位感知机制：

```python
if other_trades:
    if free_slots > 0:
        # 有空槽位时，参考其他交易平均利润
        max_market_down = -0.04
        hold_pct = (1 / free_slots) * max_market_down
        条件 += [avg_other_profit >= hold_pct]
        # 空槽位越多，越愿意持有
        # 1 个槽位 -> avg_other_profit >= -0.04
        # 4 个槽位 -> avg_other_profit >= -0.01
    else:
        # 无空槽位时，只允许最大亏损交易卖出
        条件 += [biggest_loser == True]
```

**设计哲学**：
- 有空槽位时，根据市场整体状态决定是否卖出
- 满仓时，优先止损最大亏损交易，释放资金

### 5.1 核心指标

| 指标类别 | 具体指标 | 用途 |
|---------|---------|------|
| **相对动量指数** | RMI-slow (21, 5) | 主趋势判断 |

| **趋势强度** | RMI-up-trend/dn-trend | 三周期确认 |

### 5.2 信息时间框架指标（1h）

策略使用 1 小时时间框架作为信息层，提供更高维度的趋势判断：

- **RSI_1h**: 14 周期 RSI，确保不进入极端超卖状态
- **1d_high**: 24 小时（1 天）最高价
- **3d_low**: 72 小时（3 天）最低价
- **ADR**: 平均日波动范围 (1d_high - 3d_low)

**价格定位逻辑**：
```
买入价格上限 = 3d_low + inf_pct_adr * ADR
             = 3d_low + 0.8 * ADR
```

## 六、风险管理特色

### 6.1 硬止损与动态止损结合

策略采用双重止损机制：

| 止损类型 | 阈值 | 触发条件 |
|---------|------|---------|
| 硬止损 | -40% | 固定触发 |
| 动态止损 | -3% → 0% | 持仓时间 + 趋势确认 |

**动态止损优势**：
- 初期（持仓 0-300 分钟）：止损阈值从 -3% 逐步提升
- 后期（持仓 >300 分钟）：止损阈值为 0%，保护已实现利润
- 仅在下降趋势中触发，避免震荡市误卖

### 6.2 订单超时保护

```python
def check_buy_timeout(self, pair, trade, order, **kwargs):
    # 买单超时：价格滑点 > 1% 时取消
    if current_price > order_price * 1.01:
        return True  # 取消订单
    return False

def check_sell_timeout(self, pair, trade, order, **kwargs):
    # 卖单超时：价格滑点 > 1% 时取消
    if current_price < order_price * 0.99:
        return True  # 取消订单
    return False
```

### 6.3 入场确认机制

```python
def confirm_trade_entry(self, pair, order_type, amount, rate, time_in_force, **kwargs):
    # 入场前确认：价格滑点 > 1% 时拒绝
    if current_price > rate * 1.01:
        return False  # 拒绝入场
    return True
```

**滑点保护逻辑**：
- 使用实时订单簿获取当前价格
- 订单价格与当前价格差距 > 1% 时取消/拒绝
- 防止极端行情下的不利成交

### 6.4 价格缓存机制

```python
custom_current_price_cache: TTLCache = TTLCache(maxsize=100, ttl=300)  # 5 分钟 TTL
```

**缓存策略**：
- 最大缓存 100 个交易对
- TTL 300 秒（5 分钟）
- 减少不必要的 API 调用

## 七、策略优势与局限

### ✅ 优势

1. **动态利润因子**：`ignore_roi_if_buy_signal` 机制配合动态利润因子，在趋势行情中最大化持仓收益

2. **全局仓位感知**：策略感知其他交易状态，实现跨交易的协调决策，避免满仓时误操作

3. **多层保护机制**：硬止损 + 动态止损 + 订单超时 + 入场确认，四层保护网

4. **信息层增强**：1 小时时间框架提供更高维度趋势判断，降低噪音干扰

5. **线性增长阈值**：动态调整的 RMI 阈值，适应不同持仓时长

### ⚠️ 局限

1. **仅限实盘**：`ignore_roi_if_buy_signal` 和持仓延续信号不兼容回测和超参优化

2. **止损偏宽**：40% 硬止损对保守交易者可能过于宽松

3. **依赖实时数据**：需要访问数据库查询其他交易状态，对系统稳定性要求高

4. **计算复杂度**：多指标、多时间框架、多交易感知，计算开销较大

5. **参数敏感**：买入参数经过优化，可能存在过拟合风险

## 九、适用市场环境详解

Schism 系列是 **"抄底型趋势跟踪策略"**。基于其代码架构和社区长期实盘验证的经验，它最适合 **震荡下跌后的反弹行情**，而在 **单边暴跌** 时表现不佳。

### 9.1 策略核心逻辑

- **抄底但不抄最低点**：价格定位在 3 日低点上方 80% 波动范围，留出安全边际
- **动量确认**：RMI 下降趋势中寻找反转机会，避免追高
- **趋势延续**：持仓期间通过买入信号延续机制，最大化趋势收益
- **全局协调**：感知其他交易状态，实现跨交易的资金管理

### 9.2 不同市场环境表现

| 市场类型 | 表现评级 | 原因分析 |
| :--- | :--- | :--- |
| 📈 **慢牛行情** | ⭐⭐⭐⭐⭐ | 趋势延续机制充分发挥，持仓收益最大化 |
| 🔄 **震荡行情** | ⭐⭐⭐☆☆ | 抄底信号可能多次触发，需注意手续费 |
| 📉 **单边暴跌** | ⭐⭐☆☆☆ | 抄底信号可能过早触发，止损较宽风险大 |
| ⚡️ **急涨急跌** | ⭐☆☆☆☆ | 订单超时保护可能失效，滑点风险高 |

### 9.3 关键配置建议

| 配置项 | 建议值 | 说明 |
|--------|--------|------|
| `max_open_trades` | 3-5 | 配合全局仓位感知，避免过度分散 |
| `stake_amount` | 等额分配 | 配合 `free_slots` 逻辑 |
| `timeframe` | 5m | 原生配置，不建议修改 |
| `inf_timeframe` | 1h | 信息层配置，不建议修改 |

## 十、重要提醒：复杂性的代价

### 10.1 学习成本

Schism 策略代码约 200 行，包含：
- 多时间框架指标计算
- 实时数据库查询
- 动态阈值计算
- 全局仓位感知

建议先在 **dry_run 模式** 运行至少 1 周，熟悉策略行为后再实盘。

### 10.2 硬件要求

| 交易对数量 | 最低内存 | 推荐内存 |
|-----------|---------|---------|
| 1-10 对 | 2 GB | 4 GB |
| 10-30 对 | 4 GB | 8 GB |
| 30+ 对 | 8 GB | 16 GB |

**注意**：策略需要访问数据库查询其他交易状态，多交易对场景下内存开销较大。

### 10.3 回测与实盘的差异

**关键差异**：
- `ignore_roi_if_buy_signal` 和持仓延续信号 **仅在实盘/干跑中生效**
- 回测时无法获取 `Trade.get_trades()` 数据
- 回测结果可能与实盘表现有显著差异

**建议流程**：
1. 先用回测验证买入信号质量
2. 再用 dry_run 验证动态逻辑
3. 最后小仓位实盘验证

### 10.4 手动交易者建议

Schism 的核心思想可借鉴：
- **动量确认抄底**：RMI 下降趋势中寻找反转，而非盲目抄底
- **动态止损**：持仓时间越长，止损阈值越高
- **全局视角**：考虑所有持仓的整体状态，避免满仓风险

## 十一、总结

**Schism** 是一个 **"抄底型趋势跟踪策略"**，通过 RMI 动量指标的多维度分析，结合 1 小时信息层的趋势判断，实现"抄底但不抄最低点"的交易逻辑。它的核心价值在于：

1. **动态持仓延续**：`ignore_roi_if_buy_signal` 机制在趋势行情中最大化收益
2. **全局仓位感知**：跨交易协调决策，避免资金管理失控
3. **多层保护网络**：硬止损 + 动态止损 + 订单超时 + 入场确认
4. **信息层增强**：1 小时时间框架提供高维度趋势判断

对于量化交易者而言，Schism 是一个 **实盘导向** 的策略，适合有一定经验的交易者，不建议新手直接使用。建议先用 Schism2（进化版）或从默认参数开始，逐步优化。
