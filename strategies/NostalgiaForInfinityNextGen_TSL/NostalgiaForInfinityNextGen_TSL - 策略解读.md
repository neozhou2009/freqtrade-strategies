## 一、策略概览

**NostalgiaForInfinityNextGen_TSL**（简称 NFI NextGen TSL）是 NostalgiaForInfinityNextGen 的"追踪止损强化版"。在继承 NextGen 核心多条件架构的基础上，TSL 版本对追踪止损机制进行了全面强化，旨在更好地保护利润、减少回撤。

"TSL" 代表 **Trailing Stop Loss**（追踪止损），这是本策略的核心差异化特性。相比原版 NextGen，TSL 版本在利润保护方面更加激进，适合追求稳定盈利、控制回撤的交易者。

### 核心特征

| 特征 | 描述 |
|------|------|
| **买入条件** | 16 个独立买入信号，每个条件可独立启用/禁用 |
| **卖出条件** | 6 个基础卖出信号 + 强化的追踪止损逻辑 |
| **保护机制** | 16 组买入保护参数 + 增强的追踪止损参数 |
| **时间框架** | 15 分钟主时间框架 + 1 小时信息时间框架 |
| **依赖库** | pandas, numpy, TA-Lib, technical, qtpylib, pandas_ta |
| **核心差异** | 追踪止损参数优化，利润保护更强 |

## 二、策略配置解析

### 2.1 基础风险参数

```python
# ROI 退出表（时间: 最小利润率）
minimal_roi = {
    "0": 0.10,    # 立即退出：10% 利润
    "30": 0.05,   # 30 分钟后：5% 利润
    "60": 0.02,   # 60 分钟后：2% 利润
}

# 止损设置
stoploss = -0.10  # -10% 硬止损

# 追踪止损（TSL 版本核心参数 - 强化版）
trailing_stop = True
trailing_only_offset_is_reached = True
trailing_stop_positive = 0.015   # 1.5% 追踪启动点（原版 1%）
trailing_stop_positive_offset = 0.025  # 2.5% 偏移触发（原版 3%）
trailing_stop_negative = -0.02   # -2% 负向追踪阈值（新增）
```

**设计思路**：
- 采用**时间递减 ROI** 策略，持仓时间越长，退出门槛越低
- **追踪止损强化**：TSL 版本将追踪启动点从 1% 提升至 1.5%，偏移触发从 3% 降至 2.5%
- 新增 **trailing_stop_negative** 参数，负向追踪更加敏感
- 追踪止损更早启动、更快锁定利润
- 硬止损 -10% 控制单笔最大亏损

### 2.3 TSL 参数对比 NextGen 原版

| 参数 | NextGen 原版 | TSL 强化版 | 变化说明 |
|------|-------------|-----------|---------|
| trailing_stop_positive | 0.01 (1%) | 0.015 (1.5%) | 追踪启动点提升 |
| trailing_stop_positive_offset | 0.03 (3%) | 0.025 (2.5%) | 偏移触发降低 |
| trailing_stop_negative | 无 | -0.02 (-2%) | 新增负向追踪 |

**变化解读**：
- **追踪启动点提升**：从 1% 提升至 1.5%，意味着利润达到 1.5% 时就开始追踪
- **偏移触发降低**：从 3% 降至 2.5%，更早进入追踪状态
- **新增负向追踪**：允许在利润回撤 2% 时触发追踪止损

## 四、卖出逻辑详解

### 4.1 多层止盈系统

策略采用**分级止盈**机制，根据利润率动态调整退出条件：

```
利润率区间          阈值        退出策略
────────────────────────────────────────
> 10%              立即        ROI 首级退出
5%-10%             30 分钟     ROI 次级退出
2%-5%              60 分钟     ROI 三级退出
< 2%               持仓        等待信号或止损
```

### 4.2 追踪止损机制（TSL 版本核心）

TSL 版本的追踪止损机制是核心差异化特性：

```
追踪启动条件：利润 >= 1.5%
追踪触发条件：利润 >= 2.5% 后开始追踪
追踪止损触发：利润回撤触发追踪
负向追踪阈值：利润回撤 >= 2%
```

**追踪止损流程**：
1. 利润达到 2.5% 时，追踪止损激活
2. 价格继续上涨，止损线跟随上移
3. 价格回撤时，止损线保持不动
4. 利润回撤达到阈值时，触发止损卖出

**TSL 版本优势**：
- 更早启动追踪（1.5% vs 1%）
- 更早进入追踪状态（2.5% vs 3%）
- 负向追踪保护（-2% 阈值）
- 利润保护更加积极

从 10 到 130 级别的下跌阈值保护，适应不同市场环境：

```
级别    保护强度    适用场景
────────────────────────────

80      较严格      波动市场
100     严格        高风险环境
```

- 检测周期：24h / 36h / 48h

- 与下跌保护配合使用

### 6.4 BTC 趋势过滤

部分买入条件要求 BTC 1h 非下跌趋势：

- 防止在 BTC 大跌时买入山寨币
- 降低系统性风险
- 条件 15-16 默认启用此保护

## 七、策略优势与局限

### ✅ 优势

1. **追踪止损强化**：利润保护更积极，回撤控制更好
2. **条件精炼**：16 个买入条件，覆盖主要市场环境

1. **信号频率较低**：15 分钟框架下信号频率相对较低
2. **追踪止损敏感**：可能过早退出，错过更大涨幅
3. **依赖历史数据**：需要充足的 1h 和 15m 历史数据
4. **学习曲线**：理解所有条件仍需要时间
5. **震荡市风险**：追踪止损在震荡市可能频繁触发

## 十、重要提醒：复杂性的代价

### 10.1 学习成本

虽然 TSL 版本相比 NextGen 条件更精简，但仍有 16 个买入条件需要理解。建议先从部分条件开始熟悉。

### 10.2 硬件要求

| 交易对数量 | 最低内存 | 推荐内存 |
|-----------|---------|---------|
| 20-40 对 | 2GB | 4GB |
| 40-60 对 | 4GB | 8GB |
| 60+ 对 | 8GB | 16GB |

### 10.3 回测与实盘的差异

NFI 包含动态调仓功能，这些逻辑在普通回测中难以完全模拟。建议先使用模拟交易（Dry-Run）运行 1-3 个月。

### 10.4 追踪止损的注意事项

TSL 版本的追踪止损更加敏感，需要注意：
- **震荡市风险**：可能因追踪止损频繁触发而增加交易成本
- **过早退出**：追踪启动点降低可能错过更大涨幅
- **参数调整**：根据市场特性适当调整 TSL 参数

### 10.5 手动交易者建议

适合在**大盘站上 MA20 且均线多头排列**时开启；如果全自动运行，建议开启**比特币趋势过滤**功能。15 分钟框架下，持仓周期相对较长，适合中短期趋势跟踪。
