# VecAlpha 策略筛选与评分体系设计方案 v1.0

> **文档性质**：决策基准文档（Decision Baseline）  
> **适用对象**：VecAlpha 平台策略准入流水线工程实现  
> **创建日期**：2026-04-15  
> **依据数据**：465 个策略的 strategy_registry.json、87 个策略的 2025 全年回测、代码审计报告

---

## 一、背景与核心问题

### 1.1 现状

| 项目 | 数据 |
|---|---|
| 策略总数 | 465 个 |
| 已完成全年回测 | 87 个 |
| 回测中盈利的策略 | **仅 9 个（10.3%）** |
| 达到 Sharpe > 1.0 的策略 | **仅 1 个（MACDStrategy_crossed，Sharpe=0.88，接近边界）** |
| 回测亏损 > 50% 的策略 | **18 个** |

### 1.2 核心问题

对全部 465 个策略进行完整回测存在以下问题：

1. **资源消耗极大**：单个策略全年 5m 回测约需 2-5 分钟，465 个合计需要 **16-39 小时**
2. **低价值策略占用资源**：已知大量策略属于教学示例、废弃代码、严重过拟合，约 **90% 没有商用价值**
3. **无法高效迭代**：每次新增策略或更新回测参数，都需要从头全量运行

### 1.3 设计目标

> **核心目标**：用最小资源成本，识别出真正值得回测、值得上架的策略

```
从 465 个策略中，用三阶段漏斗，以最低计算成本筛选出 10-20 个候选策略
```

## 三、阶段一：静态代码预筛

### 3.1 设计思路

不启动 Freqtrade，仅通过 Python AST 解析和正则匹配，对代码进行**零成本静态分析**。

### 3.2 硬性淘汰规则（任一命中即淘汰）

| 规则编号 | 检测项 | 淘汰条件 | 原理 |
|---|---|---|---|
| R-01 | **语法合法性** | AST 解析失败（SyntaxError） | 连解析都过不了的代码无法运行 |
| R-02 | **危险关键词检测** | 文件名或代码中含 `lookahead`、`leak` | 已知未来函数策略家族 |
| R-03 | **`shift(0)` 或 `iloc[-1]`** | 在 `populate_entry/buy` 中出现 | 常见未来视实现方式 |
| R-04 | **`do not use live`** | 代码注释中出现 | 作者自己标注不可用 |
| R-05 | **代码体量极小** | 有效代码行数 < 60 行 | 过于简单，无商业价值 |
| R-06 | **标记为测试策略** | `strategy_registry.json` 中 `features` 含 `test-strategy` | 明确标注为测试用途 |
| R-07 | **AlwaysBuy 类策略** | `populate_entry_trend` 返回全部为 `1` 无条件逻辑 | 无任何选股能力 |
| R-08 | **废弃 API** | 含 `populate_buy_trend` 且无 `populate_entry_trend` | 旧版本 API，无法在新版 Freqtrade 运行 |

### 3.3 风险标记规则（不淘汰，但标记 Warning）

| 标记 | 检测项 | 含义 |
|---|---|---|
| ⚠️ DEPRECATED_API | 使用 `populate_buy_trend`（同时也有新版） | 需要兼容性检查 |
| ⚠️ MISSING_STOPLOSS | 类中无 `stoploss` 属性定义 | 可能依赖全局配置 |
| ⚠️ MISSING_TIMEFRAME | 类中无 `timeframe` 属性定义 | 运行时可能出错 |
| ⚠️ HYPEROPT_ONLY | 使用大量 `IntParameter/DecimalParameter` 但无默认回测参数 | 无 hyperopt 无法正常回测 |
| ⚠️ MTF_USAGE | 使用 `informative_pairs` 或 `merge_informative_pair` | 多时间框架需要额外数据，回测时资源消耗更大 |

### 3.4 registry 辅助过滤

利用已有的 `strategy_registry.json` 数据进行补充筛选：

- `complexity == 1` 且 `features == []`：极简策略，优先考察是否有商业价值
- `excluded` 字段非空：明确被排除（如 `BB_RPB_TSL_2` 因 OKX 不支持 3m 数据）
- `family` 重复度：同一 `family` 超过 5 个版本，仅保留 complexity 最高的 2 个进入下一阶段

### 3.5 阶段一产出

```json
{
  "pass": ["MACDStrategy_crossed", "BinHV45", "SmoothScalp", "..."],
  "eliminated": {
    "LookaheadStrategy": "R-02: lookahead in filename",
    "AlwaysBuy": "R-06: test-strategy feature",
    "heikin": "R-04: do not use live in comments",
    "...": "..."
  },
  "warnings": {
    "BB_RPB_TSL": ["⚠️ MTF_USAGE", "⚠️ HYPEROPT_ONLY"],
    "...": ["..."]
  }
}
```

## 四、阶段二：快速回测初筛

### 4.1 设计思路

对通过阶段一的策略，使用**最近 30 天数据**进行快速回测。

目标不是评分，而是确认两件事：
1. 策略**能正常运行**（无报错）
2. 策略**不是持续亏损品**（ROI > -10%）

### 4.2 回测配置

```json
{
  "timerange": "最近30天",
  "pairs": ["BTC/USDT", "ETH/USDT"],
  "stake_amount": 1000,
  "max_open_trades": 3,
  "fee": 0.001
}
```

> **注意**：选 BTC/USDT + ETH/USDT 作为标准测试对，是因为它们流动性最好、数据最完整，是策略能否在主流市场生存的最低验证。

### 4.3 快速初筛通过标准

| 条件 | 阈值 | 说明 |
|---|---|---|
| **运行成功** | 无报错，有交易记录 | 最基本的可运行验证 |
| **ROI > -10%** | -10% | 容忍近期行情不利，但排除结构性亏损 |
| **交易次数 ≥ 3** | 3 次 | 30天内至少有3次交易，排除"从不入场"策略 |
| **无 Timeout** | 超时 < 5分钟 | 防止某些策略因 MTF 数据问题卡死 |

### 4.4 对同族策略的处理

同一 family（如 `BBRSI` 系列有 10+ 个策略），在阶段二中：
- 先全部运行快速回测
- 仅保留该 family 中得分最高的 **2 个** 进入阶段三
- 其余兄弟版本记录为 `family_deduplicated`

### 4.5 阶段二产出

```
通过策略列表（预计 ~55 个）
每个策略的 30天快速回测摘要（ROI, trades, 是否报错）
同族去重：BBRSI 系列保留 2 个 → 其余标记排除
```

## 五、阶段三：完整 VecScore 评分

### 5.1 评分总架构

**VecScore（0-100分）** = 五个维度的加权合计：

```
VecScore =
  收益能力（P）  × 0.30
+ 风控能力（R）  × 0.25
+ 稳定性（S）    × 0.20
+ 可靠性（T）    × 0.15
+ 交易效率（E） × 0.10
```

### 5.2 维度一：收益能力 P（30 分）

**测试数据**：2025 全年回测（或可用的最近12个月数据）

| 子指标 | 权重 | 计算方法 |
|---|---|---|
| ROI（总收益率） | 15 分 | 见分段得分表 |
| Profit Factor | 10 分 | 见分段得分表 |
| 平均单笔收益率 | 5 分 | `avg_profit = total_profit / trade_count` |

**ROI 分段得分表**（基于我们库的实际数据校准）：

| ROI 范围 | 得分 | 说明 |
|---|---|---|
| ROI < 0% | 0 | 亏损，此维度 0 分 |
| 0% ≤ ROI < 5% | 3 | 微盈，覆盖手续费 |
| 5% ≤ ROI < 15% | 8 | 基本可用 |
| 15% ≤ ROI < 30% | 12 | 良好（**MACDStrategy_crossed 当前水平**） |
| 30% ≤ ROI < 60% | 14 | 优秀 |
| ROI ≥ 60% | 15 | 卓越 |

> **校准说明**：原方案要求 ROI > 20% 才算合格，脱离实际。基于 87 个策略的实测分布，将 5%-15% 定义为"基本可用"，15% 以上才有商用潜力。

**Profit Factor 分段得分表**：

| Profit Factor | 得分 |
|---|---|
| < 1.0 | 0 |
| 1.0 - 1.2 | 3 |
| 1.2 - 1.5 | 6 |
| 1.5 - 2.0 | 8 |
| > 2.0 | 10 |

### 5.3 维度二：风控能力 R（25 分）⭐ 最重要

| 子指标 | 权重 | 说明 |
|---|---|---|
| 最大回撤（MDD） | 15 分 | 见分段得分表 |
| Sharpe Ratio | 10 分 | 见分段得分表 |

**MDD 分段得分表**：

| 最大回撤 | 得分 | 说明 |
|---|---|---|
| MDD > 50% | 0 | **强制降级，禁止商用** |
| 40% < MDD ≤ 50% | 3 | 极高风险 |
| 30% < MDD ≤ 40% | 7 | 高风险 |
| 20% < MDD ≤ 30% | 10 | 中等风险 |
| 10% < MDD ≤ 20% | 13 | 较低风险 |
| MDD ≤ 10% | 15 | 低风险（优秀） |

**Sharpe Ratio 分段得分**：

| Sharpe | 得分 | 说明 |
|---|---|---|
| Sharpe < 0 | 0 | 负风险调整收益 |
| 0 ≤ Sharpe < 0.5 | 2 | 差 |
| 0.5 ≤ Sharpe < 1.0 | 5 | 可接受 |
| 1.0 ≤ Sharpe < 1.5 | 7 | 良好 |
| 1.5 ≤ Sharpe < 2.0 | 9 | 优秀 |
| Sharpe ≥ 2.0 | 10 | 卓越 |

**⚠️ 风控红线（一票否决）**：

```
MDD > 40%  →  强制设置最终 VecScore ≤ 40，禁止推荐
Sharpe < 0  →  强制设置最终 VecScore ≤ 50，禁止上架
```

### 5.4 维度三：稳定性 S（20 分）

**测试方法**：对通过的策略，在**3个独立时间段**分别运行回测：

| 时间段标识 | 行情特征 | 时间范围（参考） |
|---|---|---|
| Period-A | 牛市/上涨 | 选近1年中最强上涨的3个月 |
| Period-B | 震荡/横盘 | 选近1年中上下波动的3个月 |
| Period-C | 熊市/下跌 | 选近1年中持续下跌的3个月 |

**稳定性得分计算**：

```python
# 三个时期的 ROI
rois = [roi_A, roi_B, roi_C]

# 盈利周期数得分（0-10分）
profit_periods = sum(1 for r in rois if r > 0)
period_score = profit_periods / 3 * 10  # 3个都盈利满分10分

# 收益波动性得分（0-10分）
if mean(rois) > 0:
    cv = std(rois) / abs(mean(rois))  # 变异系数
    volatility_score = max(0, 10 * (1 - min(cv, 1)))
else:
    volatility_score = 0

stability_score = period_score + volatility_score  # 满分20分
```

**关键逻辑**：

- 3个时期都盈利 → 满分 10 + 波动分
- 只在某个特定行情盈利（如只在牛市）→ 扣分严重
- 这直接惩罚了"只在 2025 某段时间有效"的过拟合策略

### 5.5 维度四：可靠性 T（15 分）

反映策略是否存在过拟合/数据偷看问题。

**检测方法一：Train/Test 分离**

将回测数据按 7:3 分割，分别计算 Train 和 Test 的 ROI：

```python
# 过拟合惩罚得分
if test_roi >= train_roi * 0.7:
    overfitting_score = 10      # 测试集表现良好，无明显过拟合
elif test_roi >= train_roi * 0.5:
    overfitting_score = 6       # 轻度过拟合
elif test_roi >= 0:
    overfitting_score = 3       # 中度过拟合，测试集仍盈利
else:
    overfitting_score = 0       # 严重过拟合，测试集亏损
```

**检测方法二：参数敏感性**（针对有 Hyperopt 参数的策略）

```python
# 对关键参数做 ±10% 扰动，观察 ROI 变化幅度
# 变化幅度 < 20% → 参数稳定，得 5 分
# 变化幅度 20-50% → 轻度敏感，得 2 分
# 变化幅度 > 50% → 高度敏感，得 0 分
# 无 Hyperopt 参数的策略 → 直接得 3 分（中性）
```

可靠性总分 = `overfitting_score (0-10)` + `param_sensitivity_score (0-5)`

### 5.6 维度五：交易效率 E（10 分）

反映策略的资金利用效率和交易频率适配性。

| 子指标 | 权重 | 计算方式 |
|---|---|---|
| 交易次数（全年） | 5 分 | 见分段 |
| 平均持仓时长 | 3 分 | 见分段 |
| 资金利用率 | 2 分 | `(avg_open_trades / max_open_trades) * 100%` |

**交易次数分段**：

| 全年交易次数 | 得分 |
|---|---|
| < 30 次 | 0（不适合实盘，统计不显著） |
| 30-100 次 | 2 |
| 100-300 次 | 4 |
| > 300 次 | 5 |

**持仓时长分段**（适用 5m 策略）：

| 平均持仓时长 | 得分 |
|---|---|
| < 15 分钟 | 1（过于激进，手续费风险高） |
| 15 分钟 - 4 小时 | 3 |
| 4 - 24 小时 | 2 |
| > 24 小时 | 1（占用资金，机会成本高） |

## 六、VecScore 等级体系与商用标准

### 6.1 等级划分

| 分数区间 | 等级 | 标识 | 平台处理 |
|---|---|---|---|
| 85 - 100 | **S 级** | 🏆 旗舰策略 | 首页重点推荐，发邮件通知订阅用户 |
| 75 - 84 | **A 级** | ⭐ 商用推荐 | 上架推荐池，可供用户订阅 |
| 65 - 74 | **B 级** | ✅ 可用 | 上架但不主推，标注"进阶用户" |
| 55 - 64 | **C 级** | ⚠️ 风险 | 仅供查阅，不允许订阅，标注风险 |
| < 55 | **D 级** | ❌ 不合格 | 禁止上架 |

### 6.2 商用强制门槛（与等级无关，必须全部满足）

```
✅ VecScore ≥ 75
✅ MDD < 30%
✅ Sharpe ≥ 0.8
✅ 全年交易次数 ≥ 100
✅ 至少 2 个时间段（共 3 段）回测为正收益
✅ 无 R-01 至 R-08 的硬性淘汰标记
✅ Train/Test 过拟合分 ≥ 6
```

> **对当前数据的现实预期**：  
> 基于 87 个策略的回测数据，预计只有 **MACDStrategy_crossed** 有可能达到 B 级以上。  
> 目前的策略库整体水平是构建商用策略市场的"起点"，而非"终点"。

### 6.3 基于实测数据的评分样例

以当前已知的策略为例：

| 策略 | P（收益） | R（风控） | S（稳定）* | T（可靠）* | E（效率） | VecScore* | 等级* |
|---|---|---|---|---|---|---|---|
| MACDStrategy_crossed | 12 | 11 | 估计14 | 估计9 | 5 | 约 **68** | **B级** |
| BinHV45 | 6 | 15 | 估计8 | 估计12 | 1 | 约 **54** | **D级** |


### 8.3 定时运行策略

| 任务 | 频率 | 说明 |
|---|---|---|
