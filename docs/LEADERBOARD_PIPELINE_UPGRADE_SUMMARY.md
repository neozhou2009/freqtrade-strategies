# 策略排行榜 UI 设计与后端数据管道升级总结

## 1. 对话背景与目标
本次对话围绕量化策略排行榜（Strategy Leaderboard）的界面设计展开。核心目标是评估现有的 UI 设计稿，并改造现有的 Freqtrade 回测数据脚本，使其能够输出符合 UI 需求的高维度商业数据。

## 2. UI 设计评估与建议
针对用户提供的排行榜设计图，评估结果如下：
*   **优点**：布局逻辑清晰（左侧筛选、顶部统计、右侧列表）、核心指标均衡（年化收益、夏普、回撤、胜率）、视觉层级分明。
*   **改进建议**：
    *   **迷你资金曲线 (Sparkline)**：将“趋势”列升级为资产净值走势图，比起单纯的排名升降更直观稳定。
    *   **最大回撤 %**：明确显示回撤百分比而非绝对值，方便跨策略对比风险。
    *   **实盘/回测标注**：增加策略可信度标签（如：[实盘 60天] / [回测]）。

## 3. 数据管道差距分析 (Gap Analysis)
在改造前，现有的 `scripts/generate_leaderboard.py` 与 UI 需求之间存在以下差距：
*   **缺项**：极度匮乏“综合评分”模型（0-100分）。
*   **漏采指标**：未提取 CAGR（年化复合收益）、最大回撤百分比、Sortino/Calmar 等风险调整收益指标。
*   **历史追踪**：完全没有跨周期的排名变动追踪能力。

## 4. 实施的改造方案

### 4.1. 综合评分系统 (Composite Scoring Algorithm)
引入了全新的 scoring 逻辑，评分区间 0–100，加权项如下：
- **CAGR (40分)**：年化复合收益率，对盈利能力的核心评估。
- **Sharpe Ratio (25分)**：衡量每承担一单位风险所获得的超额回报。
- **Max Drawdown Penalty (20分)**：最大回撤风险惩罚，>50% 回撤得0分。
- **Win Rate (10分)**：反映策略在胜率方面的稳健性。
- **Trades (5分)**：基于交易频次的数据统计显著性评分。

### 4.2. 脚本架构升级 (`scripts/generate_leaderboard.py`)
*   **全指标提取**：现在能从 Freqtrade JSON 中自动扫入 `cagr`, `max_drawdown_pct`, `sortino`, `calmar`, `profit_factor`。
*   **历史快照机制**：引入 `history.json` 自动记录排名变化，从而支持 UI 中的“排名变动趋势”列。
*   **聚合摘要**：增加了 `summary` 字段，提供所有策略的平均分、平均收益等全盘宏观数据。

## 5. 业务数据目录规划
为了保持项目根目录的整洁，将业务生成的非元数据文件从根目录移出：
*   **数据目录**：建议设为 `user_data/leaderboard/`。
*   **受影响文件**：
    *   `user_data/leaderboard/leaderboard.json` (前端 API 源)
    *   `user_data/leaderboard/LEADERBOARD.md` (阅读报告)
    *   `user_data/leaderboard/history.json` (自动排名历史)

## 6. 使用说明
使用新版本管道只需一步命令：
```bash
python scripts/generate_leaderboard.py --input-dir <数据路径> --period <时期标识>
```
脚本会自动处理评分、排名变动计算及目录生成。

## 7. 定时跑数据策略规划 (Periodic Update Strategy)

**问：对于不同时间周期，比如近1周，近1月，近半年，近1年这些，我们要如何规划定时跑数据策略？**

**答：** 为了平衡数据新鲜度与计算资源消耗，建议采用分层定时任务（Tiered Scheduling）方案：

| 榜单类型 | 覆盖时长 | 更新频率 | 定时运行时间 | 业务意义 |
| :--- | :--- | :--- | :--- | :--- |
| **近1周** | 7天 | **每日更新** | 凌晨 01:00 | 捕捉当下最热门、适应当前行情的“快刀”策略。 |
| **近1月** | 30天 | **每周更新** | 每周日 03:00 | 核心榜单，过滤掉运气成分，展示稳健的中线策略。 |
| **近半年** | 180天 | **每月更新** | 每月 1号 05:00 | 考察策略在不同行情切换（牛转熊/震荡）中的生存能力。 |
| **近1年** | 365天 | **季度更新** | 每季首日 06:00 | 长期价值榜单，用于筛选具有极高抗风险能力的明星策略。 |

**性能优化与存储建议：**
*   **分文件存储**：为支持 UI 切换，将不同周期的 JSON 独立存储（如 `leaderboard_last_1_month.json`）。
*   **自动化实现**：通过 Crontab 定时调用 `run_all_batches.py`。
*   **性能手段**：引入优先级队列（只高频更新前 100 名）及多机 Docker 并行回测。

## 8. UI 所需字段汇总 (UI Required Fields)

**问：对于策略排行榜，UI 还需要哪些字段？**

**答：** 为了实现专业级 UI，建议包含以下维度的字段：
*   **身份识别**：排名 (Rank)、名次趋势 (Rank Delta)、策略名称 (Strategy Name)、类型标签 (Tags/Styles)、运行币种 (Pairs)。
*   **核心评价**：综合评分 (Composite Score)、年化利润 (CAGR %)、夏普比率 (Sharpe Ratio)。
*   **风险控制**：最大回撤 % (Max Drawdown %)、波动率 (Volatility)、卡玛比率 (Calmar Ratio)。
*   **统计稳健性**：胜率 % (Win Rate %)、总交易次数 (Trades)、获利因子 (Profit Factor)、平均持仓时长。
*   **视觉/交互**：迷你资金曲线 (Sparkline)、操作按钮（详情/复制）。

## 9. 综合评分算法详解 (Composite Score Calculation)

**问：综合评价指标（Composite Score）是如何算出来的？**

**答：** 系统采用 0-100 的加权模型，通过 `scripts/generate_leaderboard.py` 自动计算。核心指标权重如下：

| 维度 | 权重 | 逻辑说明 |
| :--- | :--- | :--- |
| **年化回报 (CAGR)** | **40%** | 捕捉盈利能力，设定 150% 收益为封顶满分。 |
| **夏普比率 (Sharpe)** | **25%** | 衡量收益质量，设定 4.0 为封顶满分。 |
| **最大回撤惩罚 (MDD)** | **20%** | 衡量下行风险，回撤 >50% 时该项得 0 分。 |
| **胜率 (Win Rate)** | **10%** | 反映方向判断概率，胜率 >50% 才开始计分。 |
| **交易频次 (Trades)** | **5%** | 统计显著性加分，达到 500 次交易为满分。 |

**算法特性**：
*   **风控优先**：回撤大、夏普低的“赌徒策略”即便收益惊人，总分也会被迅速拉低。
*   **长期主义**：注重经过风险调整后的可持续收益。

## 10. 排行榜分类维度与排序标准 (Ranking Categories)

**问：UI 上的“综合排行”，“收益优先”，“风险调整”，“新晋策略”分别是什么标准？**

**答：** 为了满足不同风险偏好的用户，排行榜设计了四个维度的排序逻辑：
*   **综合排行 (Composite)**：默认展示。基于第 9 章定义的加权评分模型（收益、风控、稳健性三者均衡）。
*   **收益优先 (Yield First)**：纯利润导向。按 **`CAGR` (年化收益)** 从高到低排序，寻找爆发力最强的策略。
*   **风险调整 (Risk Adjusted)**：性价比导向。按 **`Sharpe Ratio` (夏普)** 或 **`Calmar Ratio` (卡玛比率)** 排序，寻找收益/回撤比最优的稳健策略。
*   **新晋策略 (New Strategies)**：新鲜度导向。按 **`Added Date` (入库时间)** 排序，或筛选最近 30 天上线的策略中短期表现最优者。

**技术实现提示**：所有维度共用同一个 `leaderboard.json` 基础数据，前端根据用户点击的 Tab 切换 `Array.sort()` 字段即可，无需重复调用后端接口。

## 11. 四大榜单具体实现算法 (Detailed Algorithms)

**问：请列出“综合排行”、“收益优先”、“风险调整”、“新晋之星”的具体排序算法。**

**答：** 为了确保前端展示的一致性，下表列出了各榜单在 `vecalpha-ranking-prototype.html` 中的具体实现逻辑：

| 榜单名称 | 核心排序字段 / 算法 | 逻辑描述 |
| :--- | :--- | :--- |
| **综合排行** | `composite_score` | 使用第 9 章定义的 5 维度加权模型，反映策略的综合作战能力。 |
| **收益优先** | `cagr` (Annualized Return) | 简单的降序排列。优先展示年化复合收益率最高的策略。 |
| **风险调整** | `Sharpe` 或 `Calmar Ratio` | **核心公式**：`Return / MaxDrawdown`。优先展示回撤极低但收益稳健的“高性价比”策略。 |
| **新晋之星** | `added_date` | **筛选条件**：最近 30 天内新增。**排序**：按加入时间倒序，辅助考察其在最近一个月的初步表现。 |

**代码实现参考 (JavaScript)**：
```javascript
const algorithms = {
    '综合': (a, b) => b.composite_score - a.composite_score,
    '收益': (a, b) => b.cagr - a.cagr,
    '风险': (a, b) => b.sharpe - a.sharpe, // 或 b.calmar - a.calmar
    '新晋': (a, b) => new Date(b.added_date) - new Date(a.added_date)
};
```

## 12. 宏观统计指标 (Summary KPIs) 与 真实性保证

**问：顶部的“有效策略”、“全盘平均分”等是如何算出来的？代码里有真实计算吗？切换时间周期它们会变吗？**

**答：** 系统顶部的 KPI 卡片是基于当前周期的所有回测结果实时统计的，具有 100% 的真实性。

*   **计算公式**：
    *   **有效策略**：当前周期成功运行并产生交易记录的策略总数。
    *   **平均分/收益/夏普**：对当前周期内所有有效策略的对应指标求算术平均值（`Sum / Count`）。
*   **代码实现**：在 `scripts/generate_leaderboard.py` 的第 148-152 行进行了集中处理：
    ```python
    summary = {
        "avg_score": round(sum(r["composite_score"] for r in results) / len(results), 1),
        "avg_cagr": round(sum(r.get("cagr", 0) for r in results) / len(results), 3),
        "avg_sharpe": round(sum(r["sharpe"] for r in results) / len(results), 2),
    }
    ```
*   **周期联动性**：**是的，切换周期时这些值一定会变。** 
    每个周期的 `leaderboard.json` 都是独立生成的。例如，行情好的月份平均分可能为 85，而震荡波动的周平均分可能仅为 50。UI 切换时会读取对应时期的 JSON 摘要，真实反映该时间跨度下的平台策略水位。
