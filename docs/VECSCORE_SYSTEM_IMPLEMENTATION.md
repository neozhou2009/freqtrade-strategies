# VecAlpha 策略筛选体系设计与实现总结

## 1. 整体架构概述

经过一系列的迭代开发，VecAlpha 量化策略自动化筛选与评分流水线 (Phase 0 -> Phase 1 -> Phase 2) 已经全面拉通，并成功对接前端的数据接口。整套系统在保证评估维度的丰富性和严谨性的同时，大幅降低了计算成本，并且高度自动化。

## 2. 三大核心阶段实现

### 🏁 Phase 0: 静态代码预筛 (`scripts/static_filter.py`)
- **功能定位**: 零回测成本拦截低劣策略，为后续昂贵的回测计算减负。
- **核心逻辑变更**: 
    - 实现了 R-01 到 R-10 共十项检查（涵盖未来视、代码报错、全量入场、超期 API 判断等硬性淘汰条件）。
    - **极简策略宽容机制**: 对有效代码行数不足惩罚这一门槛 (`MIN_CODE_LINES`) 进行了下调，由 60 行放宽至 40 行，避免误杀有意设计得极为克制的优秀策略（例如 `MACDStrategy_crossed`, `BinHV45`）。
    - **家族策略白名单保护**: 在 R-10 策略去重淘汰机制中加入保护性逻辑，不再纯粹依据文件复杂度“一刀切”。这确保了社区广泛验证过的旗舰策略（如 `NFI_ChangeToTower_V6`、`CombinedBin` 的各种衍生变种等）即使内部包含相似的组件，也不会被当成相同策略的冗余而被误杀。

### ⚡ Phase 1: 30天极速回测 (`scripts/phase1_quick_backtest.py`)
- **功能定位**: 利用近期数据快速筛除不能产生实际交易信号或存在明显结构性亏损的策略。
- **核心特性**:
    - 基于 Docker 容器化环境实现批处理。
    - 自动化剔除回测期间**交易次数不足**（< 3次）或**明显结构性亏损**（ROI < -10%）的策略。
    - 支持 `--workers N` 多线程并发压测，且可以通过 `--resume` 命令支持中断后断点续跑，完美解决大规模耗时过长难题。

### 📊 Phase 2: 全量五维评分系统 (`scripts/vecscore.py`)
- **功能定位**: 作为本项目的核心评估引擎，输出 0-100 的 `VecScore` 及 `S/A/B/C/D` 评级体系。
- **五大维度 (P/R/S/T/E)**:
    - **P (收益, 30%)**: 利润总额、Profit Factor、平均单笔盈利。
    - **R (风控, 25%)**: 最大回撤 (惩罚项极重)、Sharpe Ratio。
    - **S (稳健, 20%)**: 根据不同风格行情 (快涨/震荡/单边下行) 的背靠背回测。
    - **T (可靠/过拟合, 15%)**: 针对带 `Hyperopt` 参数的策略，通过 Train/Test 分离来检测是否过度拟合历史数据。
    - **E (效率, 10%)**: 月均开单频率、平均持仓时间损耗、资金占用率评估。
- **一票否决红线**: 为了保护商用用户，策略即使赚得再多，若 `MaxDrawdown > 40%`，其总分被硬性封顶在 40 分（D级）；若 `Sharpe Ratio < 0`，封顶 50 分；彻底将赌博型策略隔离在展示区以外。

## 3. 流水线自动化整合

### ⚙️ 中央控制台 (`scripts/run_pipeline.py`)
为了方便维护与日常操作，实现了 `run_pipeline.py`。该脚本一键串联从静态扫描到最后出分的整条工业流水线。你可以通过各种参数（比如 `--skip-phase0`, `--workers 4` 等）灵活控制任意阶段的运行和加速。

### 🖥️ 前端数据显示升级 (`scripts/generate_leaderboard.py`)
排行榜生成脚本已被改造重写：
- **无缝对接新管线**: 现在只要带上 `--vecscore user_data/vecscore_results.json` 即可读取 Phase 2 产出的五维打分结果。
- 自动提取并转换各项高级金融评估字段打入 `leaderboard.json`，确保 Web 端的看板（支持 CAGR/Sharpe/Calmar 多维度切换排名、综合评分栏位、实时动态上下排名趋势）有最新的底层数据源支持。
